# 2. Fundamental architectural principle

We need to distinguish three different levels of memory operation.

<box border radius="lg" padding={3} gap={3}>
  <box gap={1}>
    <badge color="info">Level 1</badge>
    **Temporary cognitive workspace**

    `ore_workspace` and `ore_working_memory`

    Holds the information currently being processed, including retrieved memory references and active interpretations.
  </box>
  <divider color="subtle"/>
  <box gap={1}>
    <badge color="success">Level 2</badge>
    **Long-term memory**

    `Point7MemoryStore`

    Stores episodic traces and semantic knowledge in SQLite.
  </box>
  <divider color="subtle"/>
  <box gap={1}>
    <badge color="discovery">Level 3</badge>
    **Memory transformation and generalization**

    Schema formation, analogical transfer and reconstructive memory.

    Uses stored experiences to generate more abstract representations and context-sensitive hypotheses.
  </box>
</box>

These levels must cooperate without becoming identical.

For example, a sentence in working memory should not automatically become a permanent memory. Likewise, a schema-based inference should not become an episodic fact simply because it seems plausible.

**The shared workspace is the communication mechanism; long-term memory remains the storage mechanism.**

Another important distinction: `ore_semantic.SemanticMemoryStore` is designed for word-form experiences and lexical prototypes. It should complement, not replace, Point 7's semantic knowledge store.

### Important implementation correction

There is a detail in the existing Point 7 processing order that should be addressed.

Currently, `Point7MemoryDecisionProcessor.process()` can encode the current episode before performing its retrieval operation.

This means that a newly received event may retrieve itself as though it were a previous experience.

The integration algorithm should prevent this.

Use two separate operations:

1. **Recall first:** Search previously stored memories without enabling episodic or semantic encoding routes.
2. **Encode afterward:** Once the current interpretation has been established, decide whether the new experience deserves storage.

Alternatively, refactor Point 7 into explicitly separate `recall()` and `encode()` methods.

This separation is particularly important when learning from sequences of events.

# 5. Connect the retrieved information to the remaining cognitive structures

Now we establish the actual cooperation between the modules.

## Step 9. Working memory receives and selects memory information

Working memory receives the retrieved memories and decides which ones are useful for maintaining the current interpretation.

It should not load the entire memory database.

Instead, it should retain:

- The currently relevant event.
- Selected memory evidence.
- Active semantic relationships.
- Important previous experiences.
- Unresolved information.
- References to less relevant memories.

The existing `ore_workspace.working_memory.WorkingMemoryPolicy` provides a retention-priority mechanism:

\[
P_i =
\frac{
0.35G_i+0.25R_i+0.25C_i+0.15U_i
}{1}
\]

Where:

- \(G_i\): relevance to the current goal.
- \(R_i\): recency.
- \(C_i\): contextual relevance.
- \(U_i\): unresolved-task importance.

This is an engineering prioritization rule, not a literal equation performed by the human brain.

The most important implementation detail is that working memory should keep references to long-term memories rather than duplicate their entire contents.

# 6. Cognitive control must coordinate the results

## Step 14. Collect competing interpretations

Different cognitive structures may produce different hypotheses.

For example:

| Structure | Candidate contribution |
|---|---|
| Semantic memory | Mechanic is associated with mechanical repair |
| Episodic memory | Similar previous engine-repair experience |
| Schema formation | Repair usually involves an agent and an object |
| Analogical transfer | A technician repairing a generator is structurally similar |
| Reconstructive memory | A missing outcome may be consistent with successful repair |
| Language processing | The current sentence directly supports a repair event |

These contributions must not automatically have equal authority.

## Step 15. Evaluate evidence and source independence

Introduce a common evidence evaluation function.

For interpretation \(h\):

\[
S(h)=
\sum_{g \in G}w_gE_g(h)
-\lambda C(h)
-\mu U(h)
\]

Where:

- \(G\) represents independent evidence groups.
- \(w_g\) represents source reliability.
- \(E_g(h)\) represents support or contradiction from an evidence group.
- \(C(h)\) represents conflict.
- \(U(h)\) represents unresolved information.
- \(\lambda,\mu\) control the penalties.

An important safeguard is to avoid counting the same evidence multiple times.

For example:

1. One original episode is retrieved.
2. A schema was previously learned from that episode.
3. An analogy is generated using the same episode.

These three outputs are not necessarily three independent confirmations.

They must retain references to their originating evidence.

The integrated score should therefore account for shared provenance and independence groups.

## Step 16. Select, retain alternatives or abstain

Cognitive control evaluates:

- Agreement between evidence sources.
- Contradictions.
- Memory source reliability.
- Similarity between competing interpretations.
- Whether critical information remains unresolved.
- Whether retrieving additional evidence is worthwhile.

The coordinator should select an interpretation only when its evidence and separation from competing alternatives satisfy configured thresholds.

Otherwise, it should preserve alternatives or request more information.

This fits the existing workspace conflict mechanism, which preserves competing findings rather than blindly replacing one with another.

# 7. Mathematical retrieval and information-distribution algorithm

The existing Point 7 retrieval implementation provides a starting point based on token similarity.

For episodic memories, it currently uses:

\[
R_e =
0.55L+0.30C+0.15I
\]

Where:

- \(L\): similarity with the event.
- \(C\): similarity with the context.
- \(I\): same-sequence bonus.

Semantic retrieval currently uses token similarity between the query and the stored claim.

This is a reasonable initial baseline, but it is not enough for the more sophisticated architecture described above.

I recommend gradually introducing the following retrieval model.

For episodic memories:

\[
R_e(m,q)=
w_lL+w_rR+w_cC+w_gG+w_tT+w_sS
\]

For semantic memories:

\[
R_s(m,q)=
v_cK+v_rR+v_gG+v_qQ+v_xX
\]

Where:

| Variable | Meaning |
|---|---|
| \(L\) | Lexical similarity |
| \(R\) | Relationship or event-role similarity |
| \(C\) | Context similarity |
| \(G\) | Current goal relevance |
| \(T\) | Temporal relevance |
| \(S\) | Episodic trace strength |
| \(K\) | Conceptual similarity |
| \(Q\) | Source quality and verification |
| \(X\) | Contextual compatibility |

The weights should be configurable and normalized for each memory type.

These scores rank relevant information; they must not automatically be interpreted as calibrated probabilities.

### Information distribution

After retrieval, the coordinator should distribute information based on relevance:

\[
A_m =
\sum_{j=1}^{n} a_{mj}\Delta_j
\]

Where:

- \(A_m\): activation relevance of module \(m\).
- \(a_{mj}\): sensitivity of module \(m\) to information field \(j\).
- \(\Delta_j\): magnitude of the new information in field \(j\).

This follows the existing shared-workspace subscription architecture.

A module should be activated only when the information is relevant enough to justify its computational cost.

For instance, a simple sentence may not require reconstructive memory or analogical transfer.

# 8. Complete processing pseudocode

The following is the central algorithm that connects all these components.

<CodeBlock language="python" editable>
def process_with_integrated_memory(text, goal, services):
    """
    Coordinate working memory, long-term retrieval, semantic knowledge,
    schemas, analogical transfer, reconstructive memory, and cognitive control.
    """

    # -------------------------------------------------
    # 1. Create the shared cognitive workspace
    # -------------------------------------------------

    sequence_id = services.create_sequence_id()

    workspace = services.workspace_manager.create_workspace(
        current_input=text,
        current_goal=goal,
    )

    # -------------------------------------------------
    # 2. First activate working memory
    # -------------------------------------------------

    wm_result = services.working_memory.process(
        services.make_working_memory_request(
            sequence_id=sequence_id,
            text=text,
        )
    )

    services.publish_working_memory(
        workspace=workspace,
        result=wm_result,
    )

    # -------------------------------------------------
    # 3. Generate memory retrieval cues
    # -------------------------------------------------

    snapshot = workspace.snapshot()

    query = services.build_memory_query(
        text=text,
        working_memory=wm_result.to_dict(),
        workspace=snapshot,
        goal=goal,
    )

    # -------------------------------------------------
    # 4. Retrieve old episodic and semantic memories
    #    Do not encode the current event yet.
    # -------------------------------------------------

    recall_result = services.recall_previous_memories(
        sequence_id=sequence_id,
        query=query,
        encode_episode=False,
        generalizable_knowledge=False,
    )

    # -------------------------------------------------
    # 5. Normalize and validate retrieved memories
    # -------------------------------------------------

    memories = services.normalize_memory_evidence(
        recall_result.retrieved_memories
    )

    memories = services.validate_memory_sources(memories)

    # -------------------------------------------------
    # 6. Publish memories into the shared workspace
    # -------------------------------------------------

    services.publish_retrieved_memories(
        workspace=workspace,
        memories=memories,
    )

    # -------------------------------------------------
    # 7. Reactivate working memory using relevant memories
    # -------------------------------------------------

    snapshot = workspace.snapshot()

    selected_memories = services.select_relevant_memories(
        memories=memories,
        working_memory=wm_result.to_dict(),
        goal=goal,
    )

    wm_result = services.update_working_memory(
        text=text,
        previous_state=wm_result,
        retrieved_memories=selected_memories,
        workspace=snapshot,
    )

    services.publish_working_memory(
        workspace=workspace,
        result=wm_result,
    )

    # -------------------------------------------------
    # 8. Activate semantic understanding
    # -------------------------------------------------

    semantic_result = services.semantic_processor(
        workspace=workspace,
        memories=selected_memories,
    )

    services.publish_semantic_results(
        workspace=workspace,
        result=semantic_result,
    )

    # -------------------------------------------------
    # 9. Activate relevant schemas
    # -------------------------------------------------

    schema_result = services.activate_schemas(
        event=semantic_result,
        memories=selected_memories,
    )

    # -------------------------------------------------
    # 10. Apply analogical reasoning when useful
    # -------------------------------------------------

    analogy_result = services.run_analogical_transfer(
        event=semantic_result,
        memories=selected_memories,
        schemas=schema_result,
    )

    # -------------------------------------------------
    # 11. Reconstruct incomplete memories when necessary
    # -------------------------------------------------

    reconstruction_result = None

    if services.needs_reconstruction(
        semantic_result,
        selected_memories,
    ):
        reconstruction_result = services.reconstruct_memory(
            event=semantic_result,
            memories=selected_memories,
            schemas=schema_result,
        )

    # -------------------------------------------------
    # 12. Collect all competing hypotheses
    # -------------------------------------------------

    candidates = services.collect_hypotheses(
        semantic_result=semantic_result,
        episodic_memories=selected_memories,
        schema_result=schema_result,
        analogy_result=analogy_result,
        reconstruction_result=reconstruction_result,
    )

    # -------------------------------------------------
    # 13. Cognitive control evaluates evidence
    # -------------------------------------------------

    decision = services.cognitive_control.evaluate(
        candidates=candidates,
        provenance_aware=True,
        preserve_uncertainty=True,
    )

    # -------------------------------------------------
    # 14. Publish the integrated interpretation
    # -------------------------------------------------

    services.publish_integrated_result(
        workspace=workspace,
        decision=decision,
    )

    # -------------------------------------------------
    # 15. Decide whether the current experience
    #     should be encoded into long-term memory
    # -------------------------------------------------

    if services.should_encode_episode(
        decision=decision,
        working_memory=wm_result,
    ):
        services.encode_episode(
            sequence_id=sequence_id,
            decision=decision,
            original_input=text,
        )

    # -------------------------------------------------
    # 16. Consider schema learning separately
    # -------------------------------------------------

    if services.should_update_schema(decision):
        services.update_schemas(
            decision=decision,
            feedback=services.available_verified_feedback(),
        )

    # -------------------------------------------------
    # 17. Evaluate workspace completeness
    # -------------------------------------------------

    return services.finalize_workspace(
        workspace=workspace,
        decision=decision,
        working_memory=wm_result,
    )
</CodeBlock>

The `services` methods above are proposed adapter/coordinator interfaces. They are not existing methods that should be assumed to exist in the current packages.

# 10. Biological cooperation

The computational architecture should also preserve the biological motivation of ORE.

The following is a functional mapping, not a claim that individual anatomical regions correspond one-to-one with Python classes.

| Cognitive structure | Broad biological reference | Main contribution |
|---|---|---|
| Working memory | Prefrontal and parietal networks | Active maintenance and attention |
| Episodic retrieval | Hippocampal and entorhinal networks | Event and context reactivation |
| Semantic retrieval | Distributed temporal cortical systems | Conceptual knowledge |
| Schema processing | Medial prefrontal and hippocampal interactions | Generalization and prior knowledge |
| Analogical transfer | Hippocampal, temporal and rostrolateral prefrontal interactions | Relational comparison |
| Reconstruction | Hippocampal and prefrontal interactions | Pattern completion and source monitoring |
| Cognitive control | Dorsolateral prefrontal and anterior cingulate systems | Conflict and uncertainty monitoring |

The existing modules already contain optional biological-reference simulations.

I recommend keeping their functional and biological tracks separate initially. The integration coordinator should make decisions from inspectable functional evidence rather than treating simulated neural activity as proof that a memory is accurate.

# 13. What ORE should achieve after Task 5

Consider what happens when ORE receives:

**"The mechanic repaired the engine."**

The processing sequence becomes:

1. Working memory maintains the current sentence and event representation.
2. Memory retrieval searches previous mechanic, engine and repair experiences.
3. Semantic memory supplies relevant conceptual relationships.
4. Episodic memory supplies specific prior experiences.
5. Schema formation activates typical repair-event structures.
6. Analogical transfer identifies structurally relevant experiences.
7. Reconstructive memory can help when a previously experienced event must be recalled from incomplete information.
8. Cognitive control compares all contributions, detects contradictions and preserves uncertainty.
9. The coordinator updates the shared cognitive representation.
10. The memory system decides whether the current experience should be encoded for future use.

The important transformation is that memory is no longer simply something ORE consults occasionally.

It becomes an active participant in cognitive processing.

**My recommendation is to begin with Task 5.1, then Task 5.2.** Working memory must first become connected to the shared workspace; long-term retrieval can then supply it with relevant episodic and semantic information. That gives us a stable foundation before introducing the more complicated schema, analogy and reconstruction connections.
