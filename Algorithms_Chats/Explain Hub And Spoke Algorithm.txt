# Master Algorithm: Hub-and-Spoke Semantic Concept Integration

## 1. What the algorithm must accomplish

The Hub-and-Spoke model proposes that the brain constructs a coherent concept by combining information from two interacting systems:

- **Semantic spokes:** distributed, modality-specific representations. These encode the properties of an object within particular sensory, motor, and other experience-related systems.
- **Amodal semantic hub:** a higher-level representation, associated particularly with the anterior temporal lobes (ATL), that integrates information from different modalities into a more unified conceptual representation.

For example, encountering the word *giraffe* may activate stored visual knowledge about its long neck and spotted body, knowledge about its size and habitat, and other associated information. Seeing a giraffe can activate many of the same conceptual properties through a different entry point. The hub helps make these different patterns of activation behave as knowledge about the same concept.

The algorithm below translates this proposed organization into computational stages. It is a **functional model inspired by neuroscience**, not a claim that neurons literally execute the equations shown. Mathematical operations are candidate computational analogies for processes that are biologically distributed and considerably more complex.

The architecture is not strictly one-way. Spokes provide information to the hub, while hub representations can help reactivate relevant features in the spokes. This interaction is important: a concept is not simply a list of independent features added together.

## 3. Mathematical representation of the system

Before defining the processing stages, we need a common mathematical language for the entire algorithm.

Let the semantic system contain the following modalities:

\[
M=\{V,A,T,O,S,L,E\}
\]

Where:

| Symbol | Semantic spoke | Information represented |
|---|---|---|
| \(V\) | Visual | Shape, color, size, appearance |
| \(A\) | Auditory | Sounds, voices, characteristic noises |
| \(T\) | Tactile | Texture, temperature, physical feel |
| \(O\) | Olfactory/gustatory | Smell and taste |
| \(S\) | Spatial/motor | Location, movement, manipulation, actions |
| \(L\) | Linguistic | Names, descriptions, verbal associations |
| \(E\) | Emotional/interoceptive | Feelings, internal states, bodily responses |

These are functional divisions, not a claim that each modality occupies one isolated anatomical location. Real semantic features are distributed across interacting cortical networks.

We define:

- \(x_m\): incoming information in modality \(m\).
- \(s_m\): activation pattern within spoke \(m\).
- \(W_m\): weights connecting a spoke to the hub.
- \(h\): activation pattern in the semantic hub.
- \(P_m\): hub-to-spoke feedback connections.
- \(g_m\): contribution of modality \(m\) to the current computation.
- \(c\): contextual information.
- \(\phi\): a nonlinear activation function.
- \(\eta\): learning rate.

The general semantic-processing operation is:

\[
\boxed{
\text{Input}
\rightarrow
\text{Spoke activation}
\rightarrow
\text{Hub integration}
\rightarrow
\text{Concept stabilization}
\rightarrow
\text{Semantic retrieval}
}
\]

The crucial computational property is that the hub must learn relationships between features, not simply memorize independent sensory properties. The mappings between observable features and conceptual significance are often nonlinear. [Cite](turn208216view1)

# 4. Detailed algorithmic processing stages

## Stage 1. Receive conceptual information through different input channels

**Objective:** Receive information about an entity or object, regardless of how the brain encounters it.

The brain can encounter the same concept through several different routes:

1. Reading the written word `giraffe`.
2. Hearing someone pronounce the word `giraffe`.
3. Looking at a photograph of a giraffe.
4. Seeing a real giraffe.
5. Touching or interacting with an object associated with the concept.
6. Recalling a previously encountered giraffe from memory.

These inputs are physically different, but they can eventually activate overlapping conceptual knowledge.

### Algorithmic operations

**Operation 1.1 — Receive input**

Represent the incoming information as:

\[
X=\{x_1,x_2,\ldots,x_n\}
\]

Each element contains some information about the encountered entity.

For example, a visual observation might contain:

\[
x_V=
\begin{bmatrix}
\text{shape}\\
\text{color}\\
\text{body proportions}\\
\text{visible patterns}\\
\text{relative size}
\end{bmatrix}
\]

A linguistic input might contain:

\[
x_L=\text{Encoded representation of the word giraffe}
\]

**Operation 1.2 — Determine the available information channels**

The system determines which modality-specific pathways are receiving information.

Mathematically:

\[
A_m=
\begin{cases}
1 & \text{if modality }m\text{ has relevant input}\\
0 & \text{otherwise}
\end{cases}
\]

This is a simplified representation of input availability, not a literal binary switch in the brain.

**Operation 1.3 — Preserve simultaneous information**

When multiple modalities provide information about the same entity, their signals must remain available for integration.

For example:

\[
X=\{x_V,x_A,x_S,x_L\}
\]

A person sees a giraffe, hears it make a noise, and hears another person say its name.

The brain can process these sources in parallel, although their activation and processing times need not be identical.

**Possible mathematical operations:**

- Signal encoding.
- Feature extraction.
- Parallel processing.
- Temporal synchronization.
- Signal normalization.

## Stage 2. Activate the appropriate modality-specific semantic spokes

<AsyncImage query="human brain cortical lobes labeled visual auditory somatosensory motor cortex anterior temporal lobe neuroscience anatomical illustration" aspectRatio="16:9" width="100%" maxHeight={230} fit="contain"/>

**Objective:** Activate the distributed neural systems responsible for representing the particular properties of the encountered entity.

The semantic system does not initially require all information to be represented in one location.

Instead, different properties are associated with different modality-specific systems.

For example:

- Visual knowledge about stripes activates visual association systems.
- Knowledge about an animal's characteristic sounds activates auditory systems.
- Knowledge about running activates movement-related systems.
- Knowledge about touching its skin activates somatosensory systems.
- Knowledge about its name activates linguistic systems.

### Algorithmic operations

**Operation 2.1 — Route information to the relevant spoke**

For every available modality:

\[
x_m\rightarrow S_m
\]

Where \(S_m\) represents the corresponding semantic spoke network.

**Operation 2.2 — Activate relevant neural populations**

The incoming information changes the activation of neurons representing associated features.

A simplified activation equation is:

\[
s_m=\phi_m(W_m^{input}x_m+b_m)
\]

Where:

- \(x_m\) is the modality-specific input.
- \(W_m^{input}\) represents input connections.
- \(b_m\) represents baseline biases.
- \(\phi_m\) represents nonlinear neuronal activation.

For example, a visual input might activate populations associated with:

\[
s_V=
\begin{bmatrix}
0.95\\
0.90\\
0.80\\
0.20
\end{bmatrix}
\]

These values are illustrative activation strengths, not measured firing rates.

They might correspond to:

- Long neck: 0.95.
- Spotted body: 0.90.
- Four-legged body: 0.80.
- Particular color: 0.20.

**Operation 2.3 — Preserve distributed feature representations**

A concept is not necessarily represented by one neuron per characteristic.

Instead, multiple neural populations contribute to a distributed activation pattern.

Consequently:

\[
\text{Conceptual feature}
\neq
\text{Single neuron}
\]

A more appropriate computational representation is:

\[
s_m=[a_1,a_2,\ldots,a_k]
\]

Where each \(a_i\) represents the activation of a population or computational unit.

**Possible mathematical operations:**

- Matrix multiplication.
- Nonlinear activation.
- Population coding.
- Sparse activation.
- Distributed representation.
- Thresholding.
- Signal normalization.

## Stage 3. Extract individual semantic features from each spoke

**Objective:** Convert the activity within each modality-specific network into information that can contribute to the identification of the concept.

This stage distinguishes individual features from the complete conceptual representation.

For example, the visual spoke may provide:

\[
F_V=
\{
\text{long neck},
\text{spotted body},
\text{four legs},
\text{small horns}
\}
\]

The motor-related spoke might provide:

\[
F_S=
\{
\text{walking},
\text{running},
\text{neck movement},
\text{feeding movement}
\}
\]

The auditory spoke might provide:

\[
F_A=
\{
\text{vocalization},
\text{environmental sounds}
\}
\]

### Algorithmic operations

**Operation 3.1 — Identify active features**

Determine which feature representations are sufficiently activated.

For a feature \(i\):

\[
f_i=
\begin{cases}
1 & a_i>\theta_i\\
0 & a_i\leq\theta_i
\end{cases}
\]

Where \(\theta_i\) is a conceptual activation threshold.

Biologically, activation is graded rather than necessarily binary.

**Operation 3.2 — Estimate feature strength**

Instead of treating every feature equally, preserve its degree of activation:

\[
F_m=[f_1,f_2,\ldots,f_k]
\]

**Operation 3.3 — Preserve feature relationships**

Some properties are meaningful in relation to other properties.

For example:

- Long neck.
- Height.
- Reaching leaves.

These features can contribute to an interconnected representation rather than three completely independent facts.

An illustrative feature-association matrix is:

\[
R_m(i,j)=\operatorname{Association}(f_i,f_j)
\]

This matrix represents learned relationships between features.

**Operation 3.4 — Make feature information available to the hub**

Each spoke prepares its feature activation pattern for integration with the other spokes.

\[
F_m\rightarrow \text{ATL input pathway}
\]

**Possible mathematical operations:**

- Feature detection.
- Threshold functions.
- Activation weighting.
- Vector construction.
- Correlation.
- Association matrix formation.
- Pattern encoding.

## Stage 4. Retrieve previously acquired semantic feature information

**Objective:** Supplement current sensory information with knowledge acquired through earlier experiences.

This is important because the brain does not need to encounter every property of an entity each time it identifies that entity.

For example, when you hear the word *giraffe*, you may retrieve visual and biological knowledge even though no actual giraffe is present.

The linguistic input can reactivate stored semantic information through learned relationships.

### Algorithmic operations

**Operation 4.1 — Search for associated representations**

A feature or linguistic representation activates related representations in semantic memory.

An illustrative associative activation equation is:

\[
a_j^{new}
=
a_j^{old}
+
\sum_i R_{ij}a_i
\]

Where:

- \(a_i\) is the activation of an existing feature.
- \(R_{ij}\) is the learned association between features.
- \(a_j^{new}\) is the resulting activation of another feature.

**Operation 4.2 — Reactivate features from previous experiences**

The brain can reactivate features that are not currently available through sensory input.

For instance:

\[
\text{Word: giraffe}
\rightarrow
\text{Retrieved visual properties}
\]

This allows the system to access knowledge without directly observing the object.

**Operation 4.3 — Combine current and previously stored information**

\[
F_m^{combined}
=
\alpha F_m^{current}
+
(1-\alpha)F_m^{memory}
\]

Here, \(\alpha\) represents the relative contribution of current sensory evidence.

The value of this coefficient would depend on the particular computational model and conditions.

**Operation 4.4 — Maintain uncertainty**

Previously learned knowledge may be incomplete or inaccurate.

Therefore, the system should not necessarily treat every retrieved property as equally reliable.

Represent confidence as:

\[
C_i\in[0,1]
\]

The confidence value can later influence integration.

**Possible mathematical operations:**

- Associative activation.
- Pattern completion.
- Memory retrieval.
- Vector addition.
- Weighted combination.
- Confidence estimation.
- Recurrent activation.

## Stage 5. Transmit information from the spokes toward the ATL hub

<AsyncImage query="anterior temporal lobe semantic hub and spoke model neuroscience brain network diagram sensory motor modality spoke connections" aspectRatio="16:9" width="100%" maxHeight={230} fit="contain"/>

**Objective:** Transfer information from the distributed modality-specific networks into the transmodal integration system.

This is one of the most important architectural stages.

The spokes contain different types of information. The hub needs to receive these different activation patterns in a form that allows them to contribute to a shared conceptual representation.

### Algorithmic operations

**Operation 5.1 — Transform spoke activation into transmitted signals**

For each modality:

\[
u_m=W_m s_m
\]

Where:

- \(s_m\) is the spoke activation vector.
- \(W_m\) is the learned spoke-to-hub connectivity matrix.
- \(u_m\) is the transmitted activation pattern.

The matrix can transform the dimensionality and organization of the spoke representation.

**Operation 5.2 — Apply connectivity-dependent influence**

Not every feature has an equally strong connection to the hub.

The contribution of a feature depends on the learned connectivity between the spoke and the integration network.

For example:

\[
u_V=W_Vs_V
\]

\[
u_A=W_As_A
\]

\[
u_S=W_Ss_S
\]

Each produces a different representation, but the outputs are directed toward the same conceptual integration system.

**Operation 5.3 — Preserve multiple sources of information**

Instead of replacing one modality with another, the system maintains their contributions:

\[
U=\{u_V,u_A,u_T,u_O,u_S,u_L,u_E\}
\]

**Operation 5.4 — Allow information to be exchanged through learned connections**

The hub-and-spoke architecture depends on the connectivity between distributed representations.

The hub can therefore receive information from a modality that did not directly receive the original input.

For example:

\[
\text{Linguistic activation}
\rightarrow
\text{ATL}
\rightarrow
\text{Visual semantic knowledge}
\]

This is a crucial property of the architecture.

**Possible mathematical operations:**

- Weighted projection.
- Matrix multiplication.
- Dimensional transformation.
- Signal transmission.
- Connectivity-weighted activation.
- Parallel information propagation.

## Stage 6. Estimate and combine the contributions of different modalities

**Objective:** Determine how information from the different spokes should contribute to the current conceptual representation.

The integration process should not assume that all modalities are equally important for every concept.

For example, identifying a particular fruit might depend heavily on visual and taste information, while understanding a musical instrument might depend more on auditory and motor information.

The importance of a modality can also change depending on the quality of the available evidence.

### Algorithmic operations

**Operation 6.1 — Estimate the contribution of each modality**

Let:

\[
q_m=\text{Current relevance or reliability of modality }m
\]

A computational model can convert these values into normalized weights:

\[
g_m=
\frac{e^{q_m}}
{\sum_{j=1}^{M}e^{q_j}}
\]

This is the softmax function.

It provides:

\[
\sum_{m=1}^{M}g_m=1
\]

**Operation 6.2 — Modulate each spoke's contribution**

\[
\tilde{u}_m=g_mu_m
\]

A highly relevant or reliable source can contribute more strongly than an unreliable one.

This weighting mechanism is a useful computational implementation, but the exact softmax calculation is not an established description of a biological operation in the ATL.

**Operation 6.3 — Prepare the combined activation**

\[
U_{combined}
=
\sum_{m=1}^{M}\tilde{u}_m
\]

This creates a combined signal for the subsequent integration process.

Importantly, this is only a preliminary combination. It does not yet solve the full problem of forming a coherent concept.

**Operation 6.4 — Preserve conflicting evidence**

Suppose an image resembles a giraffe but has a body shape inconsistent with other retrieved features.

The integration network must allow competing interpretations rather than immediately accepting every activated feature as correct.

An illustrative inconsistency value is:

\[
D_{ij}=\operatorname{Distance}(u_i,u_j)
\]

High disagreement can prompt additional retrieval, feedback, or further processing.

**Possible mathematical operations:**

- Softmax normalization.
- Weighted summation.
- Reliability estimation.
- Signal gating.
- Competition.
- Similarity and distance calculations.
- Uncertainty estimation.

## Stage 7. Integrate the different features inside the amodal semantic hub

<AsyncImage query="anterior temporal lobe bilateral ventral temporal cortex anatomical neuroscience brain illustration" aspectRatio="16:9" width="100%" maxHeight={210} fit="contain"/>

<badge color="success">Central integration stage</badge>

**Objective:** Transform separate modality-specific representations into a coherent conceptual representation.

This is the central operation proposed by the Hub-and-Spoke model.

Consider the following information:

| Source | Activated information |
|---|---|
| Visual spoke | Long neck, spotted body |
| Motor spoke | Walking, running, feeding |
| Auditory spoke | Characteristic vocalizations |
| Linguistic spoke | Word giraffe |
| Spatial spoke | Tall body, environmental location |
| Other semantic knowledge | Animal, mammal, herbivore |

None of these sources independently provides the complete concept.

The ATL is proposed to develop an integrated representation that captures the relationships between them.

### Algorithmic operations

**Operation 7.1 — Receive the combined spoke information**

The hub receives:

\[
U_{combined}
=
\sum_mg_mW_ms_m
\]

**Operation 7.2 — Transform the combined information into an integrated representation**

A simplified equation is:

\[
h=
\phi\left(
W_hU_{combined}+b_h
\right)
\]

Where:

- \(W_h\) represents the integration network's learned transformations.
- \(b_h\) represents its biases.
- \(\phi\) is a nonlinear activation function.
- \(h\) is the resulting hub representation.

**Operation 7.3 — Detect combinations of features**

This is particularly important.

The hub should not simply learn:

- Giraffe = long neck.
- Giraffe = spotted body.
- Giraffe = animal.

It should learn the combined pattern of properties and their conceptual significance.

For example:

\[
\begin{aligned}
&\text{Long neck}\\
&+\text{Spotted body}\\
&+\text{Animal structure}\\
&+\text{Characteristic behavior}\\
&\Downarrow\\
&\text{Integrated giraffe representation}
\end{aligned}
\]

A nonlinear transformation can create representations that depend on combinations of inputs.

For example, a two-layer computational network could implement:

\[
h=\phi_2(W_2\phi_1(W_1U+b_1)+b_2)
\]

This allows the model to learn complex feature combinations that cannot be adequately represented by simply adding independent properties.

**Operation 7.4 — Detect conceptual relationships**

The hub can learn that two objects are conceptually similar even when their physical properties are not identical.

For example:

- Apples and bananas have different shapes.
- Their colors and textures differ.
- Their physical properties are not identical.

Nevertheless, they share meaningful conceptual relationships as fruits.

The hub can therefore encode common structure across different modality-specific patterns.

**Operation 7.5 — Generate a distributed hub activation pattern**

The result is not necessarily a single semantic identifier.

Instead:

\[
h_c=[h_1,h_2,\ldots,h_n]
\]

Each concept can have its own distributed pattern of activity.

These patterns form a representational space in which related concepts can have more similar activation patterns than unrelated concepts.

This general idea is supported by computational hub-and-spoke models in which hidden hub units develop distributed representations through learning across verbal and sensory-motor inputs. [Cite](turn680924view0)

**Possible mathematical operations:**

- Nonlinear transformations.
- Matrix multiplication.
- Feature conjunction.
- Distributed representation.
- Cross-modal integration.
- Representation learning.
- Pattern similarity.
- Statistical abstraction.

## Stage 8. Stabilize the integrated concept through recurrent processing

**Objective:** Refine the hub representation until it becomes sufficiently consistent to support conceptual identification.

Integration does not have to be completed in one computational pass.

The hub and spokes can interact repeatedly.

### Algorithmic operations

**Operation 8.1 — Maintain the current hub state**

Let:

\[
h_t=\text{Hub activation at iteration }t
\]

**Operation 8.2 — Recalculate the hub activation**

The next state can depend on its previous activation and newly arriving information:

\[
h_{t+1}
=
\phi\left(
W_{hh}h_t+
\sum_mg_mW_ms_m+
b_h
\right)
\]

Where \(W_{hh}\) represents recurrent connections within the hub-related network.

**Operation 8.3 — Update the representation**

Each iteration changes the hub activation according to the combined information.

For example, an initially incomplete activation pattern might gradually become more consistent with a known concept as additional features become available.

**Operation 8.4 — Evaluate the degree of stabilization**

A simplified convergence criterion is:

\[
\Delta_t=\|h_{t+1}-h_t\|
\]

If:

\[
\Delta_t<\epsilon
\]

the representation is considered sufficiently stable for the purposes of the computational model.

If not, another update takes place.

**Operation 8.5 — Maintain competing candidate concepts when needed**

Suppose the received information is consistent with several animals.

The system should not necessarily settle on one concept prematurely.

It can maintain competing patterns until further information resolves the ambiguity.

**Possible mathematical operations:**

- Recurrent neural dynamics.
- Iterative updating.
- Feedback integration.
- Attractor-like settling.
- Euclidean distance.
- Convergence testing.
- Competitive activation.

The recurrent equations are a proposed computational implementation, not evidence that the ATL is a simple isolated attractor network.

## Stage 9. Send integrated semantic information back to the modality-specific spokes

**Objective:** Use the integrated hub representation to reactivate and refine information in the corresponding modality-specific systems.

This is an important part of the architecture that can be overlooked when treating the model as a simple feedforward pipeline.

The interaction is bidirectional.

For example, hearing the word *giraffe* may activate the hub representation, which can then help reactivate visual knowledge about a giraffe's appearance.

### Algorithmic operations

**Operation 9.1 — Project hub activation toward the spokes**

For each modality:

\[
\hat{s}_m=W_m^{feedback}h
\]

Where:

- \(h\) is the integrated concept representation.
- \(W_m^{feedback}\) represents hub-to-spoke connections.
- \(\hat{s}_m\) is the predicted or reactivated spoke representation.

**Operation 9.2 — Reactivate relevant features**

For example:

\[
h_{\text{giraffe}}
\rightarrow
\begin{cases}
\text{Visual features}\\
\text{Movement features}\\
\text{Auditory associations}\\
\text{Linguistic information}
\end{cases}
\]

**Operation 9.3 — Compare predicted and currently available features**

An illustrative prediction error is:

\[
e_m=s_m-\hat{s}_m
\]

A large difference indicates that the current spoke information differs from the information predicted by the integrated representation.

This can contribute to further refinement.

**Operation 9.4 — Reconcile spoke and hub activity**

The system can use the feedback and incoming information to update both representations:

\[
s_m^{t+1}
=
\phi_m
\left(
W_{input,m}x_m+
W_{feedback,m}h_t
\right)
\]

The hub can then be updated using the refined spoke activities.

**Operation 9.5 — Continue bidirectional interaction**

Repeat the integration and feedback processes as required.

\[
\text{Spokes}
\rightleftarrows
\text{Hub}
\]

An empirical study using fMRI investigated this dynamic connectivity and reported flexible coupling between the ATL and action-related and place-related cortical networks, including bidirectional influences. [Cite](turn763903search10)

**Possible mathematical operations:**

- Top-down projection.
- Predictive activation.
- Pattern completion.
- Prediction-error calculation.
- Feedback correction.
- Recurrent network updating.
- Bidirectional message passing.

## Stage 10. Develop a modality-independent conceptual representation

<badge color="success">Amodal representation</badge>

**Objective:** Ensure that the same underlying concept can be accessed through different modalities.

This is one of the defining properties of the Hub-and-Spoke model.

Consider three different inputs:

\[
I_1=\text{Written word: giraffe}
\]

\[
I_2=\text{Picture of a giraffe}
\]

\[
I_3=\text{Spoken word: giraffe}
\]

Each input activates different initial pathways.

However, they should eventually activate overlapping semantic representations.

### Algorithmic operations

**Operation 10.1 — Produce a hub representation from each input**

\[
h_L=H(I_1)
\]

\[
h_V=H(I_2)
\]

\[
h_A=H(I_3)
\]

**Operation 10.2 — Identify shared conceptual structure**

The system develops representations that preserve information about the entity while reducing dependence on the exact form of the input.

The desired property is:

\[
h_L\approx h_V\approx h_A
\]

This does not mean the activation patterns must be mathematically identical.

Instead, they should share an underlying representational structure sufficient to identify the same concept.

**Operation 10.3 — Distinguish modality-specific information from shared information**

The conceptual system must preserve two kinds of information:

\[
H=H_{\text{shared}}+H_{\text{specific}}
\]

Here, the equation is a conceptual decomposition:

- \(H_{\text{shared}}\) describes cross-modal conceptual properties.
- \(H_{\text{specific}}\) describes information that remains associated with particular modalities.

For example, seeing a giraffe directly provides visual details that hearing its name cannot provide.

The hub does not need to erase these distinctions. It needs to integrate their shared conceptual significance.

**Operation 10.4 — Establish a stable representation across input conditions**

A useful computational measure is cosine similarity:

\[
\operatorname{sim}(h_a,h_b)
=
\frac{h_a\cdot h_b}
{\|h_a\|\|h_b\|}
\]

Higher similarity between different input routes to the same concept would indicate stronger modality-invariant representation.

**Possible mathematical operations:**

- Cross-modal alignment.
- Similarity measurement.
- Feature abstraction.
- Representation normalization.
- Invariant feature learning.
- Pattern correspondence.

**Important distinction:** An amodal representation does not mean that the ATL is completely disconnected from sensory information. Its proposed amodal function emerges from integrating information supplied by the modality-specific networks.

## Stage 11. Identify the concept and retrieve its semantic identity

**Objective:** Determine which known concept best explains the integrated activation.

At this stage, the system has a sufficiently developed hub representation and can compare it with learned conceptual patterns.

### Algorithmic operations

**Operation 11.1 — Access candidate concept representations**

Let the semantic memory contain:

\[
C=\{c_1,c_2,\ldots,c_N\}
\]

Each concept has a learned hub representation:

\[
P_c=[p_1,p_2,\ldots,p_n]
\]

**Operation 11.2 — Calculate similarity between the current representation and stored concepts**

\[
S(c)=\operatorname{sim}(h,P_c)
\]

For each candidate concept, calculate its representational similarity.

**Operation 11.3 — Rank possible concepts**

\[
c^*=\arg\max_{c\in C}S(c)
\]

The candidate with the greatest similarity becomes the leading interpretation.

**Operation 11.4 — Evaluate identification confidence**

One simplified method is to compare the highest candidate score against competing scores:

\[
Conf=
S(c_1)-S(c_2)
\]

Where \(c_1\) and \(c_2\) are the highest- and second-highest-scoring candidates.

A small difference indicates ambiguity.

**Operation 11.5 — Request more information when necessary**

If the identification is uncertain, the system can retrieve additional features or continue processing new input.

For example, the long neck alone might suggest a giraffe, but other features can strengthen or weaken that interpretation.

**Possible mathematical operations:**

- Vector similarity.
- Pattern matching.
- Nearest-neighbor retrieval.
- Ranking.
- Competition.
- Confidence estimation.
- Threshold-based selection.

---

## Stage 12. Construct category relationships and generalize across concepts

**Objective:** Use integrated conceptual representations to establish relationships between different entities and recognize shared conceptual properties.

This operation allows the brain to go beyond recognizing individual objects.

For example, after integrating the concepts of a giraffe, horse, zebra, and cow, the semantic system can establish that they share certain broader properties.

The system can learn:

- Giraffe → animal.
- Zebra → animal.
- Horse → animal.
- Cow → animal.

It can also distinguish differences between them.

### Algorithmic operations

**Operation 12.1 — Compare the representations of different concepts**

For two concepts:

\[
S(c_i,c_j)=
\frac{P_{c_i}\cdot P_{c_j}}
{\|P_{c_i}\|\|P_{c_j}\|}
\]

This gives a simplified measure of conceptual similarity.

**Operation 12.2 — Identify shared features**

For two feature representations, identify their overlapping properties.

For example:

\[
F_{\text{horse}}\cap F_{\text{zebra}}
\]

Might contain:

\[
\{\text{animal},\text{four-legged},\text{mammal}\}
\]

**Operation 12.3 — Identify distinguishing features**

Calculate the difference between representations:

\[
D(F_i,F_j)=F_i-F_j
\]

A more suitable implementation for binary feature sets would use set differences or symmetric differences.

For example:

\[
F_{\text{zebra}}\setminus F_{\text{horse}}
\]

could contain the characteristic striped appearance.

**Operation 12.4 — Establish superordinate categories**

A group of related concepts can contribute to a more abstract category representation.

One possible computational approximation is:

\[
P_{\text{animal}}
=
\frac{1}{N}
\sum_{i=1}^{N}P_{c_i}
\]

This calculates the average of several concept representations.

Biological category learning is more sophisticated than averaging vectors, but this provides a useful mathematical analogy.

**Operation 12.5 — Learn taxonomic relationships**

The system establishes hierarchical relationships:

\[
\text{Giraffe}
\rightarrow
\text{Mammal}
\rightarrow
\text{Animal}
\rightarrow
\text{Living organism}
\]

**Operation 12.6 — Learn associative relationships**

Not all semantic relationships depend on shared characteristics.

For example:

- Knife and butter.
- Key and lock.
- Cup and coffee.

These objects can be strongly associated because they frequently occur together in meaningful situations, even though they do not share many physical properties.

A computational model can represent the relationship through co-occurrence statistics:

\[
A(i,j)=\operatorname{Association}(c_i,c_j)
\]

It can also use temporal information:

\[
A(i,j)\propto P(c_j\mid c_i,\text{context})
\]

This allows semantic representations to reflect both similarity and experience-based associations.

The importance of distinguishing taxonomic similarity from associative relationships is discussed in the computational Controlled Semantic Cognition literature. [Cite](turn680924view0)

**Possible mathematical operations:**

- Vector similarity.
- Intersection and difference.
- Clustering.
- Prototype formation.
- Hierarchical categorization.
- Graph construction.
- Conditional probability.
- Co-occurrence estimation.
- Relational learning.

## Stage 13. Apply semantic control to select task-relevant knowledge

<AsyncImage query="human brain left inferior frontal gyrus posterior middle temporal gyrus inferior parietal cortex labeled semantic control network neuroscience illustration" aspectRatio="16:9" width="100%" maxHeight={210} fit="contain"/>

**Objective:** Select the appropriate parts of an integrated concept according to the current task or situation.

This stage is particularly important because activating a concept does not mean that every piece of associated knowledge should be used at once.

Consider the concept *giraffe*.

Different tasks require different information:

| Task | Relevant semantic information |
|---|---|
| Describe its appearance | Neck, spots, body shape |
| Classify it | Mammal, animal |
| Compare it with a zebra | Stripes versus spots |
| Explain its feeding | Height, leaves, neck |
| Recognize its sound | Auditory characteristics |

The brain needs mechanisms that constrain semantic retrieval according to the current goal.

This is associated with the Controlled Semantic Cognition framework, which distinguishes semantic representation from semantic control. The latter involves a distributed network including the left inferior frontal gyrus, posterior middle temporal gyrus, and inferior parietal regions. [Cite](turn763903search0) [Cite](turn763903search5)

### Algorithmic operations

**Operation 13.1 — Receive the current task**

Define:

\[
Q=\text{Current cognitive objective}
\]

For example:

\[
Q=\text{Find the visual differences between a giraffe and a zebra}
\]

**Operation 13.2 — Identify task-relevant semantic features**

Let:

\[
R_i=\text{Relevance of feature }i\text{ to task }Q
\]

The system estimates how useful each activated feature is for the current objective.

**Operation 13.3 — Increase the activation of relevant features**

One computational approximation is:

\[
a_i' = a_i+\lambda R_i
\]

Where:

- \(a_i\) is the previous activation.
- \(R_i\) is task relevance.
- \(\lambda\) determines the influence of the task.

**Operation 13.4 — Suppress or reduce irrelevant information**

\[
a_i''=a_i'-\mu I_i
\]

Where \(I_i\) describes the degree to which a feature is irrelevant or competing with the current objective.

The brain does not necessarily eliminate irrelevant information. Rather, control mechanisms can alter which information receives priority during processing.

**Operation 13.5 — Retrieve the selected semantic information**

\[
F_{\text{selected}}
=
\{f_i:a_i''>\theta\}
\]

This gives the feature information most useful for the current task.

**Operation 13.6 — Reconfigure interactions with the spokes**

The control system can bias interactions with the relevant modality-specific regions.

For example:

- Visual comparison → greater emphasis on visual features.
- Action reasoning → greater emphasis on motor-related properties.
- Verbal definition → greater emphasis on linguistic information.

**Possible mathematical operations:**

- Attention weighting.
- Selective activation.
- Inhibition.
- Relevance scoring.
- Dynamic gating.
- Context-dependent retrieval.
- Competitive selection.

**Important architectural distinction:** This stage is an extension of the basic Hub-and-Spoke representation system. The semantic hub represents conceptual information; the control network determines how that information is selected and used.

## Stage 14. Generate the required conceptual output

**Objective:** Make the integrated and selected semantic information available for a particular behavior.

The final output depends on the original task.

For example, the brain may need to:

- Recognize an object.
- Name it.
- Describe it.
- Explain its properties.
- Compare it with another object.
- Select an appropriate action.

### Algorithmic operations

**Operation 14.1 — Receive the selected concept representation**

\[
H_{\text{output}}=h_{\text{selected}}
\]

This represents the integrated information relevant to the task.

**Operation 14.2 — Retrieve the required features**

For a verbal description:

\[
F_{\text{output}}
=
\{\text{long neck},\text{spotted body},\text{tall animal}\}
\]

For an identification task, the system may only need the concept identity.

**Operation 14.3 — Route the semantic representation toward the appropriate output system**

For example:

\[
h
\rightarrow
\begin{cases}
\text{Language production}\\
\text{Action planning}\\
\text{Decision-making}\\
\text{Recognition response}
\end{cases}
\]

These output systems are not simply components of the ATL itself.

**Operation 14.4 — Generate the behavioral response**

For example:

\[
\text{Integrated concept}
\rightarrow
\text{Giraffe}
\rightarrow
\text{Verbal response}
\]

Or:

\[
\text{Integrated concept}
\rightarrow
\text{Animal category}
\rightarrow
\text{Classification response}
\]

**Possible mathematical operations:**

- Semantic readout.
- Feature selection.
- Classification.
- Decision thresholds.
- Action selection.
- Response mapping.
- Motor or linguistic output encoding.

# 5. Learning algorithm: How the hub and spokes acquire conceptual knowledge

The previous stages explain how the system processes concepts that have already been acquired.

However, the architecture also needs a learning mechanism capable of constructing these representations through experience.

This is a separate but continuously interacting process.

The brain must learn how features from different modalities belong to the same entities, how they relate to one another, and which combinations distinguish one concept from another.

## Stage 15. Acquire information across multiple experiences

**Objective:** Build semantic knowledge from repeated interactions with objects, words, events, and situations.

Consider a child encountering a giraffe.

During different experiences, the child might:

- See the animal at a zoo.
- Hear its name.
- Observe its long neck.
- See it eating leaves.
- Hear other people describing it.
- See different giraffes in books.

Each experience provides incomplete information.

### Algorithmic operations

**Operation 15.1 — Receive an experience**

Represent each episode as:

\[
E_t=
\{x_V,x_A,x_S,x_L,x_E,\ldots\}
\]

Not every episode contains every modality.

**Operation 15.2 — Activate the relevant spokes**

Each experience activates the appropriate feature networks.

\[
E_t\rightarrow\{s_m(t)\}
\]

**Operation 15.3 — Activate the shared hub**

The simultaneously or sequentially available feature patterns contribute to the hub:

\[
h_t=\phi\left(\sum_mW_ms_m(t)+b\right)
\]

**Operation 15.4 — Accumulate information across experiences**

Over time, information about different encounters contributes to the learned conceptual representation.

\[
H_c=
\operatorname{Learn}(E_1,E_2,\ldots,E_n)
\]

This is not simply the accumulation of all features. It involves learning which features are consistently associated with the concept and how they relate.

**Operation 15.5 — Distinguish stable properties from incidental properties**

Suppose a child encounters several giraffes:

| Experience | Observed property |
|---|---|
| Giraffe 1 | Spotted body, long neck |
| Giraffe 2 | Spotted body, long neck |
| Giraffe 3 | Spotted body, long neck |
| Giraffe 4 | Different coloration, long neck |

The system should learn which features are characteristic of the concept and which can vary.

A possible computational representation is:

\[
P(f_i\mid c)
\]

This estimates how strongly feature \(f_i\) is associated with concept \(c\).

**Operation 15.6 — Develop more generalizable representations**

Features that occur consistently across experiences can contribute strongly to the stable conceptual representation.

Other features can remain as variable or experience-specific information.

**Possible mathematical operations:**

- Incremental learning.
- Statistical estimation.
- Feature co-occurrence.
- Probability estimation.
- Pattern abstraction.
- Regularization.
- Generalization.

---

## Stage 16. Learn the mappings between the spokes and the hub

<AsyncImage query="neural network diagram multiple input layers shared hidden layer multimodal representation learning" aspectRatio="16:9" width="100%" maxHeight={200} fit="contain"/>

**Objective:** Develop the connections that allow different modality-specific representations to activate a common concept.

This is essential to the hub's proposed function.

The brain must learn that different patterns of sensory and linguistic activity can describe the same entity.

### Algorithmic operations

**Operation 16.1 — Create initial connections**

The spokes and the hub are connected through distributed neural pathways.

In a simplified computational model:

\[
W_V,W_A,W_T,W_S,W_L,\ldots
\]

represent the different connection matrices.

**Operation 16.2 — Generate hub representations from multimodal inputs**

\[
h=
\phi\left(
W_Vs_V+
W_As_A+
W_Ts_T+\cdots
\right)
\]

**Operation 16.3 — Learn to reconstruct or predict associated information**

When the system receives the word *giraffe*, it should learn to activate relevant information in the other modalities.

For example:

\[
\text{Giraffe word}
\rightarrow
\text{Visual properties of giraffe}
\]

When it receives visual input, it should also activate the appropriate conceptual and linguistic information.

**Operation 16.4 — Calculate prediction errors**

For a target feature vector \(y_m\) and predicted feature vector \(\hat y_m\):

\[
e_m=y_m-\hat y_m
\]

A simplified squared-error function is:

\[
L_m=\frac{1}{2}\|y_m-\hat y_m\|^2
\]

This measures the mismatch between what the system predicted and what it should have activated.

**Operation 16.5 — Adjust the connection strengths**

One possible computational learning rule is:

\[
W_m^{new}
=
W_m^{old}
-
\eta\frac{\partial L}{\partial W_m}
\]

Where \(\eta\) controls the size of the learning adjustment.

This is a gradient-based implementation. It should not be interpreted as proof that biological synapses use standard backpropagation.

**Operation 16.6 — Strengthen frequently co-activated relationships**

An additional simplified learning principle is Hebbian-style plasticity:

\[
\Delta w_{ij}
=
\eta a_i a_j
\]

Where the connection between two active populations changes according to their joint activity.

Real biological plasticity also depends on timing, neuromodulation, inhibition, and other factors.

**Operation 16.7 — Repeat learning over multiple episodes**

\[
W^{t+1}=W^t+\Delta W^t
\]

Gradual adjustments help the system acquire representations that become increasingly consistent across different experiences.

The computational literature has demonstrated implemented hub-and-spoke networks in which shared hidden units learn to map verbal information and sensory-motor properties into distributed conceptual representations. [Cite](turn208216view1)

---

## Stage 17. Develop modality-invariant representations through cross-modal learning

**Objective:** Learn that different sensory and linguistic patterns can refer to the same conceptual identity.

This stage is closely related to Stage 10, but there is an important distinction:

- Stage 10 uses the already developed representations during normal processing.
- Stage 17 explains how the system can learn the cross-modal relationships in the first place.

### Algorithmic operations

**Operation 17.1 — Present different forms of the same concept**

For example:

\[
\{I_{\text{word}},I_{\text{image}},I_{\text{sound}}\}
\]

All refer to the same entity.

**Operation 17.2 — Produce separate hub activations**

\[
h_1=H(I_{\text{word}})
\]

\[
h_2=H(I_{\text{image}})
\]

\[
h_3=H(I_{\text{sound}})
\]

**Operation 17.3 — Learn their shared conceptual structure**

The system adjusts connectivity so that different routes produce compatible representations.

A possible computational learning objective is:

\[
L_{\text{cross}}
=
\sum_{i,j}
y_{ij}
\|h_i-h_j\|^2
\]

Where \(y_{ij}=1\) when two inputs represent the same concept.

In a fuller contrastive model, inputs referring to different concepts would also be encouraged to remain distinguishable.

**Operation 17.4 — Preserve individual modality details**

Cross-modal integration should not make every input representation identical.

For instance, an image contains specific color and shape information that the spoken word does not supply.

The shared representation should capture conceptual identity while allowing the spokes to preserve additional sensory details.

**Operation 17.5 — Test generalization with previously unseen examples**

The system should recognize another giraffe even if its appearance differs from the examples encountered during learning.

This tests whether it has learned a coherent concept rather than memorized individual observations.

**Possible mathematical operations:**

- Cross-modal alignment.
- Contrastive learning.
- Similarity optimization.
- Generalization.
- Pattern separation.
- Feature abstraction.
- Representation stability.

---

## Stage 18. Continuously update semantic knowledge

**Objective:** Adapt semantic representations when new information or experiences become available.

Semantic knowledge is not necessarily fixed after its initial acquisition.

For example, a person might initially associate giraffes primarily with their appearance and later learn additional information about:

- Their biological classification.
- Their diet.
- Their habitat.
- Their social behavior.
- Their evolutionary characteristics.

### Algorithmic operations

**Operation 18.1 — Detect new semantic information**

\[
X_{\text{new}}\neq X_{\text{stored}}
\]

**Operation 18.2 — Compare the new information with existing knowledge**

\[
e_{\text{knowledge}}
=
X_{\text{new}}-\hat X_{\text{stored}}
\]

This is a conceptual prediction-error representation.

**Operation 18.3 — Evaluate the credibility and consistency of new information**

Not every new observation should automatically overwrite established knowledge.

The system must evaluate the new evidence in relation to existing knowledge.

**Operation 18.4 — Update the appropriate spoke**

If the new information concerns a particular modality, its representation and corresponding connections may change.

**Operation 18.5 — Update the hub representation**

Where new information changes the broader conceptual structure, the hub's learned connections may also be adjusted.

**Operation 18.6 — Preserve previously acquired knowledge**

Learning should not unnecessarily destroy useful earlier information.

This is related to the broader problems of memory consolidation, interference, and catastrophic forgetting in computational models.

**Possible mathematical operations:**

- Incremental parameter updates.
- Prediction-error correction.
- Bayesian-style evidence updating.
- Weighted learning.
- Memory consolidation.
- Interference management.
- Stability-plasticity regulation.

# 6. Modeling semantic impairment: What happens when the hub or spokes are damaged?

This stage is especially important because it allows us to connect the computational algorithm with the clinical evidence that motivated the Hub-and-Spoke model.

It also gives us a way to test whether our architecture actually reproduces the proposed biological functions.

## Stage 19. Simulate degradation of the amodal semantic hub

<AsyncImage query="semantic dementia anterior temporal lobe bilateral atrophy brain MRI comparison healthy brain neuroscience illustration" aspectRatio="16:9" width="100%" maxHeight={210} fit="contain"/>

**Objective:** Understand how damage to the ATL integration system changes semantic processing.

Semantic dementia (SD) is associated with progressive anterior temporal lobe degeneration and deterioration of conceptual knowledge.

Patients can experience difficulties with:
- Understanding words.
- Recognizing and naming pictures.
- Retrieving object properties.
- Identifying objects through different sensory experiences.
- Accessing specific conceptual information.

The important observation is that impairments can extend across multiple sensory and linguistic modalities.

This is consistent with the proposal that the ATL contributes to a shared conceptual representation rather than processing only one particular sensory channel. Neuropsychological, neuroimaging, and TMS findings provide converging evidence for this proposal. [Cite](turn763903search9) [Cite](turn208216view1)

### Algorithmic operations

**Operation 19.1 — Reduce the functioning of hub units**

Let the healthy hub representation be:

\[
h=[h_1,h_2,\ldots,h_n]
\]

Introduce a degradation matrix:

\[
D_h=
\begin{bmatrix}
d_1&0&\cdots&0\\
0&d_2&\cdots&0\\
\vdots&\vdots&\ddots&\vdots\\
0&0&\cdots&d_n
\end{bmatrix}
\]

Where:

\[
0\leq d_i\leq1
\]

The impaired representation is:

\[
h'=D_hh
\]

Values closer to zero represent greater loss of the corresponding computational contribution.

This is a model of functional degradation, not a literal equation for neurodegeneration.

**Operation 19.2 — Reduce the ability to integrate features**

The system becomes less capable of combining separate features into coherent concepts.

For example:

\[
\{\text{long neck},\text{spots},\text{animal}\}
\]

May remain partially accessible as separate properties, while their integration into a sufficiently specific giraffe representation deteriorates.

**Operation 19.3 — Reduce conceptual specificity**

The distinction between similar concepts becomes increasingly difficult.

For example:

\[
\operatorname{sim}(h_{\text{giraffe}},h_{\text{zebra}})
\]

May become less useful for distinguishing the two concepts if their detailed representations are degraded.

**Operation 19.4 — Measure semantic acuity**

Define an illustrative discrimination score:

\[
A_c=S(c_{\text{correct}})
-
S(c_{\text{nearest competitor}})
\]

A smaller value means the system has greater difficulty distinguishing related concepts.

This provides a computational interpretation of the deterioration of semantic acuity.

**Operation 19.5 — Test conceptual performance across modalities**

Evaluate whether the impaired system can still identify the same concept when receiving:

- A written word.
- A spoken word.
- A visual image.
- Other sensory information.

A hub impairment should produce difficulties that extend across multiple input modalities, although the severity of impairment may differ between tasks.

**Operation 19.6 — Preserve residual broader knowledge where possible**

The model should allow a graded pattern of deterioration.

For example, a patient may lose specific knowledge about the appearance of a zebra while retaining a broader association with animals.

However, this is not an absolute preservation rule. As semantic deterioration advances, broader conceptual knowledge can also become impaired.

The severity and pattern of semantic loss depend on the extent and distribution of degeneration. [Cite](turn763903search11) [Cite](turn763903search1)

---

## Stage 20. Simulate damage to individual semantic spokes

**Objective:** Understand how damage to a modality-specific network differs from damage to the shared hub.

The two types of impairment should produce distinguishable patterns.

For example, damage affecting visual semantic representations can disproportionately impair knowledge of visual properties while leaving some auditory or action-related knowledge relatively better preserved.

### Algorithmic operations

**Operation 20.1 — Select an impaired spoke**

For example:

\[
S_V=\text{Visual semantic spoke}
\]

**Operation 20.2 — Reduce its activity**

\[
s_V'=D_Vs_V
\]

**Operation 20.3 — Recalculate information reaching the hub**

\[
h'=
\phi\left(
W_Vs_V'
+
W_As_A
+
W_Ss_S
+\cdots
\right)
\]

**Operation 20.4 — Evaluate modality-specific performance**

The system should show reduced access to visual features, but it may retain some knowledge through the remaining spokes.

For example, it might still know that a particular animal makes characteristic sounds or performs characteristic actions despite impaired visual semantic information.

**Operation 20.5 — Compare the results with hub damage**

| Characteristic | Hub damage | Spoke damage |
|---|---|---|
| Cross-modal integration | Broadly affected | May remain relatively preserved |
| Visual semantic information | Can deteriorate | Particularly affected if visual spoke is damaged |
| Auditory semantic information | Can deteriorate | Relatively preserved if auditory spoke is intact |
| Conceptual specificity | Often reduced across modalities | More dependent on the damaged spoke |
| General conceptual knowledge | Can progressively deteriorate | May be supported by other spokes |

**Possible mathematical operations:**

- Selective parameter degradation.
- Matrix masking.
- Ablation.
- Activation reduction.
- Cross-modal performance comparison.
- Error measurement.

---

## Stage 21. Simulate damage to the connections between the hub and spokes

**Objective:** Understand the importance of connectivity, rather than considering the hub and spokes as isolated structures.

Even if the hub and individual spokes remain functional, impairing their connections can disrupt the communication required for conceptual integration.

### Algorithmic operations

**Operation 21.1 — Identify the connection matrix**

\[
W_m=\text{Connectivity between spoke }m\text{ and the hub}
\]

**Operation 21.2 — Introduce connection degradation**

\[
W_m'=D_mW_m
\]

Where \(D_m\) reduces the effectiveness of selected connections.

**Operation 21.3 — Calculate the resulting hub input**

\[
u_m'=W_m's_m
\]

**Operation 21.4 — Recalculate the integrated representation**

\[
h'=\phi\left(\sum_m u_m'+b_h\right)
\]

**Operation 21.5 — Test whether the remaining connections compensate**

If multiple pathways remain, the system may still recover some conceptual information through other sources.

**Operation 21.6 — Evaluate the behavioral consequences**

Compare:

- Normal hub and spokes.
- Damaged hub.
- Damaged individual spoke.
- Damaged hub-to-spoke connections.

This gives the computational architecture a way to reproduce different types of semantic impairment.

Research on white-matter connectivity and semantic dementia also highlights the importance of connections linking anterior temporal regions with distributed semantic networks. [Cite](turn763903search13)

# 7. Complete master algorithm in pseudocode

The following pseudocode combines the processing stages into one integrated computational procedure.

It distinguishes normal semantic processing from longer-term learning.

<CodeBlock language="python" editable>
# HUB-AND-SPOKE SEMANTIC INTEGRATION
#
# Functional computational model inspired by neuroscience.
# The equations are candidate implementations, not literal
# measurements of individual neuronal computations.

MODALITIES = [
    "visual",
    "auditory",
    "tactile",
    "olfactory_gustatory",
    "spatial_motor",
    "linguistic",
    "emotional_interoceptive"
]

def semantic_processing(input_data, task, memory):

    # 1. Receive input
    available_inputs = encode_input(input_data)

    # 2. Activate modality-specific spokes
    spoke_activations = {}

    for modality in MODALITIES:
        if modality in available_inputs:
            spoke_activations[modality] = (
                activate_spoke(
                    modality,
                    available_inputs[modality]
                )
            )

    # 3. Extract individual features
    spoke_features = {}

    for modality, activation in spoke_activations.items():
        spoke_features[modality] = extract_features(
            modality,
            activation
        )

    # 4. Retrieve previously learned semantic information
    retrieved_features = retrieve_associations(
        spoke_features,
        memory
    )

    # 5. Combine current and retrieved information
    combined_features = combine_current_and_memory(
        spoke_features,
        retrieved_features
    )

    # 6. Transmit information to the ATL hub
    hub_inputs = {}

    for modality, features in combined_features.items():
        hub_inputs[modality] = spoke_to_hub(
            modality,
            features
        )

    # 7. Estimate the contribution of each modality
    modality_weights = estimate_modality_reliability(
        hub_inputs,
        task
    )

    # 8. Integrate information in the amodal hub
    hub_state = initialize_hub()

    for iteration in range(MAX_ITERATIONS):

        previous_state = hub_state.copy()

        hub_state = integrate_hub(
            previous_state,
            hub_inputs,
            modality_weights
        )

        # 9. Send feedback to the spokes
        feedback = hub_to_spokes(hub_state)

        spoke_activations = update_spokes(
            spoke_activations,
            feedback,
            available_inputs
        )

        # 10. Refine the hub using updated spoke activity
        hub_inputs = {
            modality: spoke_to_hub(
                modality,
                activation
            )
            for modality, activation in
            spoke_activations.items()
        }

        # 11. Check convergence
        if difference(hub_state, previous_state) < EPSILON:
            break

    # 12. Identify the concept
    candidates = retrieve_candidate_concepts(
        hub_state,
        memory
    )

    concept = rank_candidates(candidates)

    # 13. Evaluate confidence
    confidence = calculate_confidence(candidates)

    # 14. Apply semantic control
    selected_features = semantic_control(
        concept,
        spoke_activations,
        task
    )

    # 15. Retrieve conceptual relationships
    relations = retrieve_relations(
        concept,
        memory
    )

    # 16. Generate requested response
    result = generate_output(
        concept,
        selected_features,
        relations,
        task
    )

    # 17. Update semantic memory when appropriate
    if should_learn(input_data, result):
        update_semantic_memory(
            input_data,
            spoke_activations,
            hub_state,
            memory
        )

    return {
        "concept": concept,
        "confidence": confidence,
        "spoke_activations": spoke_activations,
        "hub_representation": hub_state,
        "selected_features": selected_features,
        "semantic_relations": relations,
        "output": result
    }
</CodeBlock>

# 8. Complete mathematical operation registry

Here is a consolidated registry of the principal mathematical operations in the algorithm.

| No. | Operation | Mathematical implementation | Main function |
|---:|---|---|---|
| 1 | Input encoding | Vector encoding | Represent input |
| 2 | Spoke activation | Nonlinear transformation | Activate modality-specific information |
| 3 | Feature extraction | Thresholding and population coding | Extract properties |
| 4 | Associative retrieval | Weighted activation | Reactivate stored information |
| 5 | Memory combination | Weighted addition | Combine old and new information |

# 10. Important biological limitations and interpretation

There are several important distinctions to preserve when turning the theory into a Python architecture or a formal brain-inspired algorithm.

**A. The ATL is not necessarily one isolated integration point.**

The model describes the ATL as an amodal hub, but the biological architecture is distributed. The anterior temporal regions have different connectivity patterns and graded functional specializations. The precise anatomical boundaries and contributions of individual ATL subregions remain debated. <Cite refs={["turn763903search13","turn763903search0"]}/>

**B. The hub does not replace the spokes.**

The integrated representation depends on information supplied by distributed modality-specific networks. Damage to the hub and damage to an individual spoke should therefore produce different impairment patterns.

**C. The hub is not simply an averaging mechanism.**

A simple summation of the inputs would be insufficient to explain complex conceptual representations. Nonlinear feature combinations and learned relationships are important.

**D. The softmax, cosine similarity, gradient descent, and other mathematical operations are candidate implementations.**

We cannot currently conclude that the biological brain performs these exact numerical calculations. Their purpose is to provide computationally testable explanations of the proposed functions.

**E. Semantic control is a distinct but interacting system.**

If we want to simulate the whole semantic cognition process, the ATL hub and spokes alone are insufficient. Task-dependent retrieval and selection must also be represented.

# 6. Modeling semantic impairment: What happens when the hub or spokes are damaged?

This stage is especially important because it allows us to connect the computational algorithm with the clinical evidence that motivated the Hub-and-Spoke model.

It also gives us a way to test whether our architecture actually reproduces the proposed biological functions.

## Stage 19. Simulate degradation of the amodal semantic hub

<AsyncImage query="semantic dementia anterior temporal lobe bilateral atrophy brain MRI comparison healthy brain neuroscience illustration" aspectRatio="16:9" width="100%" maxHeight={210} fit="contain"/>

**Objective:** Understand how damage to the ATL integration system changes semantic processing.

Semantic dementia (SD) is associated with progressive anterior temporal lobe degeneration and deterioration of conceptual knowledge.

Patients can experience difficulties with:
- Understanding words.
- Recognizing and naming pictures.
- Retrieving object properties.
- Identifying objects through different sensory experiences.
- Accessing specific conceptual information.

The important observation is that impairments can extend across multiple sensory and linguistic modalities.

This is consistent with the proposal that the ATL contributes to a shared conceptual representation rather than processing only one particular sensory channel. Neuropsychological, neuroimaging, and TMS findings provide converging evidence for this proposal. [Cite](turn763903search9) [Cite](turn208216view1)

### Algorithmic operations

**Operation 19.1 — Reduce the functioning of hub units**

Let the healthy hub representation be:

\[
h=[h_1,h_2,\ldots,h_n]
\]

Introduce a degradation matrix:

\[
D_h=
\begin{bmatrix}
d_1&0&\cdots&0\\
0&d_2&\cdots&0\\
\vdots&\vdots&\ddots&\vdots\\
0&0&\cdots&d_n
\end{bmatrix}
\]

Where:

\[
0\leq d_i\leq1
\]

The impaired representation is:

\[
h'=D_hh
\]

Values closer to zero represent greater loss of the corresponding computational contribution.

This is a model of functional degradation, not a literal equation for neurodegeneration.

**Operation 19.2 — Reduce the ability to integrate features**

The system becomes less capable of combining separate features into coherent concepts.

For example:

\[
\{\text{long neck},\text{spots},\text{animal}\}
\]

May remain partially accessible as separate properties, while their integration into a sufficiently specific giraffe representation deteriorates.

**Operation 19.3 — Reduce conceptual specificity**

The distinction between similar concepts becomes increasingly difficult.

For example:

\[
\operatorname{sim}(h_{\text{giraffe}},h_{\text{zebra}})
\]

May become less useful for distinguishing the two concepts if their detailed representations are degraded.

**Operation 19.4 — Measure semantic acuity**

Define an illustrative discrimination score:

\[
A_c=S(c_{\text{correct}})
-
S(c_{\text{nearest competitor}})
\]

A smaller value means the system has greater difficulty distinguishing related concepts.

This provides a computational interpretation of the deterioration of semantic acuity.

**Operation 19.5 — Test conceptual performance across modalities**

Evaluate whether the impaired system can still identify the same concept when receiving:

- A written word.
- A spoken word.
- A visual image.
- Other sensory information.

A hub impairment should produce difficulties that extend across multiple input modalities, although the severity of impairment may differ between tasks.

**Operation 19.6 — Preserve residual broader knowledge where possible**

The model should allow a graded pattern of deterioration.

For example, a patient may lose specific knowledge about the appearance of a zebra while retaining a broader association with animals.

However, this is not an absolute preservation rule. As semantic deterioration advances, broader conceptual knowledge can also become impaired.

The severity and pattern of semantic loss depend on the extent and distribution of degeneration. [Cite](turn763903search11) [Cite](turn763903search1)

### Algorithmic operations

**Operation 20.2 — Reduce its activity**

**Operation 20.3 — Recalculate information reaching the hub**

**Operation 20.4 — Evaluate modality-specific performance**

The system should show reduced access to visual features, but it may retain some knowledge through the remaining spokes.

For example, it might still know that a particular animal makes characteristic sounds or performs characteristic actions despite impaired visual semantic information.

**Operation 20.5 — Compare the results with hub damage**

|---|---|---|

## Stage 21. Simulate damage to the connections between the hub and spokes

**Objective:** Understand the importance of connectivity, rather than considering the hub and spokes as isolated structures.

Even if the hub and individual spokes remain functional, impairing their connections can disrupt the communication required for conceptual integration.

### Algorithmic operations

**Operation 21.1 — Identify the connection matrix**

\[
W_m=\text{Connectivity between spoke }m\text{ and the hub}
\]

**Operation 21.2 — Introduce connection degradation**

\[
W_m'=D_mW_m
\]

Where \(D_m\) reduces the effectiveness of selected connections.

**Operation 21.3 — Calculate the resulting hub input**

\[
u_m'=W_m's_m
\]

**Operation 21.4 — Recalculate the integrated representation**

\[
h'=\phi\left(\sum_m u_m'+b_h\right)
\]

**Operation 21.5 — Test whether the remaining connections compensate**

If multiple pathways remain, the system may still recover some conceptual information through other sources.

**Operation 21.6 — Evaluate the behavioral consequences**

Compare:

- Normal hub and spokes.
- Damaged hub.
- Damaged individual spoke.
- Damaged hub-to-spoke connections.

This gives the computational architecture a way to reproduce different types of semantic impairment.

Research on white-matter connectivity and semantic dementia also highlights the importance of connections linking anterior temporal regions with distributed semantic networks. [Cite](turn763903search13)

# 7. Complete master algorithm in pseudocode

The following pseudocode combines the processing stages into one integrated computational procedure.

It distinguishes normal semantic processing from longer-term learning.

<CodeBlock language="python" editable>
# HUB-AND-SPOKE SEMANTIC INTEGRATION
#
# Functional computational model inspired by neuroscience.
# The equations are candidate implementations, not literal
# measurements of individual neuronal computations.

MODALITIES = [
    "visual",
    "auditory",
    "tactile",
    "olfactory_gustatory",
    "spatial_motor",
    "linguistic",
    "emotional_interoceptive"
]

def semantic_processing(input_data, task, memory):

    # 1. Receive input
    available_inputs = encode_input(input_data)

    # 2. Activate modality-specific spokes
    spoke_activations = {}

    for modality in MODALITIES:
        if modality in available_inputs:
            spoke_activations[modality] = (
                activate_spoke(
                    modality,
                    available_inputs[modality]
                )
            )

    # 3. Extract individual features
    spoke_features = {}

    for modality, activation in spoke_activations.items():
        spoke_features[modality] = extract_features(
            modality,
            activation
        )

    # 4. Retrieve previously learned semantic information
    retrieved_features = retrieve_associations(
        spoke_features,
        memory
    )

    # 5. Combine current and retrieved information
    combined_features = combine_current_and_memory(
        spoke_features,
        retrieved_features
    )

    # 6. Transmit information to the ATL hub
    hub_inputs = {}

    for modality, features in combined_features.items():
        hub_inputs[modality] = spoke_to_hub(
            modality,
            features
        )

    # 7. Estimate the contribution of each modality
    modality_weights = estimate_modality_reliability(
        hub_inputs,
        task
    )

    # 8. Integrate information in the amodal hub
    hub_state = initialize_hub()

    for iteration in range(MAX_ITERATIONS):

        previous_state = hub_state.copy()

        hub_state = integrate_hub(
            previous_state,
            hub_inputs,
            modality_weights
        )

        # 9. Send feedback to the spokes
        feedback = hub_to_spokes(hub_state)

        spoke_activations = update_spokes(
            spoke_activations,
            feedback,
            available_inputs
        )

        # 10. Refine the hub using updated spoke activity
        hub_inputs = {
            modality: spoke_to_hub(
                modality,
                activation
            )
            for modality, activation in
            spoke_activations.items()
        }

        # 11. Check convergence
        if difference(hub_state, previous_state) < EPSILON:
            break

    # 12. Identify the concept
    candidates = retrieve_candidate_concepts(
        hub_state,
        memory
    )

    concept = rank_candidates(candidates)

    # 13. Evaluate confidence
    confidence = calculate_confidence(candidates)

    # 14. Apply semantic control
    selected_features = semantic_control(
        concept,
        spoke_activations,
        task
    )

    # 15. Retrieve conceptual relationships
    relations = retrieve_relations(
        concept,
        memory
    )

    # 16. Generate requested response
    result = generate_output(
        concept,
        selected_features,
        relations,
        task
    )

    # 17. Update semantic memory when appropriate
    if should_learn(input_data, result):
        update_semantic_memory(
            input_data,
            spoke_activations,
            hub_state,
            memory
        )

    return {
        "concept": concept,
        "confidence": confidence,
        "spoke_activations": spoke_activations,
        "hub_representation": hub_state,
        "selected_features": selected_features,
        "semantic_relations": relations,
        "output": result
    }
</CodeBlock>
