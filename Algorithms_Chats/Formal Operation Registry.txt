# Integrated Reading Algorithm — Formal Operation Registry

The master algorithm should be represented as a **numbered registry of computational operations**, rather than a simple list of psychological models. Each operation will have a stable ID, defined inputs and outputs, processing rules, mathematical computations where applicable, and dependencies on other operations.

One important architectural distinction: the Dual-Route, Interactive-Activation, TRACE, Cohort, Shortlist B, and Connectionist models are not six consecutive stages of reading. They describe complementary or competing mechanisms for different aspects of language recognition. The registry will therefore integrate their useful mechanisms into coordinated processing modules without incorrectly treating the models as a single biological sequence.

## 1. Registry specification

<box border radius="lg" gap={3} padding={3}>
  **Registry identifier**

  <title size="xl" color="default">IRA-REG-001</title>
  <text color="secondary" size="sm">Integrated Reading Algorithm — Master Operation Registry</text>
  <divider color="subtle"/>
  | Property | Specification |
  |---|---|
  | Registry version | 1.0 |
  | Operation namespace | IRA-OP |
  | Total operations | 62 |
  | Architecture | Parallel, interactive, cascaded, and Bayesian |
  | Primary modalities | Visual text and auditory speech |
  | Main processing objective | Word recognition, pronunciation, and meaning |
  | Output | Recognized lexical items and integrated meaning |
</box>

### 1.1 Standard operation record

Every operation follows this formal record:

| Field | Meaning |
|---|---|
| Operation ID | Unique, permanent identifier |
| Name | Operation's computational function |
| Inputs | Information required |
| Processing | What the operation executes |
| Mathematical model | Relevant computational representation |
| Outputs | Information produced |
| Dependencies | Operations supplying its inputs |
| Execution type | Sequential, parallel, recurrent, or conditional |

### 1.2 Execution conventions

The registry distinguishes four execution types:

- **Sequential:** requires completion of a previous operation.
- **Parallel:** runs alongside other operations.
- **Recurrent:** repeats until a stopping criterion is reached.
- **Conditional:** executes only when its task or input requires it.

Mathematical equations below are computational abstractions suitable for implementing the proposed architecture. They are not assertions that the biological brain literally executes the same software instructions or equations.

# 2. Operation group A — Reading initialization and input preparation

<badge color="info">Operations 001–004</badge>

These operations initialize the reading process and establish the information that subsequent operations will process.

### IRA-OP-001 — Initialize Reading Transaction

**Inputs**
- Reading request.
- Current processing state.
- Available lexical and semantic resources.

**Processing**

1. Create a new reading-processing instance.
2. Allocate working memory for the current input.
3. Initialize lexical candidate storage.
4. Initialize phonological candidate storage.
5. Initialize semantic candidate storage.
6. Initialize contextual information.
7. Set processing status to active.

**Mathematical representation**

\[
S_0=\{V,L,P,M,C,T\}
\]

Where:

- \(V\): visual representation.
- \(L\): lexical representation.
- \(P\): phonological representation.
- \(M\): semantic representation.
- \(C\): context.
- \(T\): processing time.

**Output:** Initialized processing state.

**Execution:** Sequential.

### IRA-OP-002 — Determine Input Modality and Reading Task

**Inputs**
- Input signal.
- Task instructions.

**Processing**

Identify whether the system must process:

1. Written language.
2. Spoken language.
3. Written language for silent comprehension.
4. Written language for pronunciation.
5. Written language for both comprehension and pronunciation.

**Mathematical representation**

\[
Q\in\{
\text{visual},
\text{auditory},
\text{visual-comprehension},
\text{visual-pronunciation},
\text{combined}
\}
\]

**Output:** Task and modality configuration.

**Execution:** Conditional.

### IRA-OP-003 — Acquire Input Signal

**Inputs**
- Written text or auditory signal.

**Processing**

For visual input:
- Acquire the visual character information.
- Preserve spatial ordering.
- Preserve character boundaries when available.

For auditory input:
- Acquire the acoustic waveform.
- Preserve its temporal structure.
- Divide it into processing frames.

**Mathematical representation**

Visual:

\[
X_v=\{x_1,x_2,\ldots,x_n\}
\]

Auditory:

\[
X_a(t)=s(t)
\]

**Output:** Raw input representation.

**Execution:** Sequential.

### IRA-OP-004 — Normalize and Organize Input

**Inputs**
- Raw visual or auditory input.

**Processing**

For visual input:
- Normalize spatial dimensions.
- Adjust for variations in character size.
- Compensate for positional differences.
- Preserve character-order information.

For auditory input:
- Normalize signal amplitude where appropriate.
- Organize acoustic frames.
- Preserve temporal relationships.

**Mathematical representation**

\[
X'=\frac{X-\mu_X}{\sigma_X+\epsilon}
\]

This is an illustrative normalization operation, not a claim about the exact biological normalization mechanism.

**Output:** Normalized input signal.

**Dependencies:** OP-003.

**Execution:** Sequential.

# 3. Operation group B — Visual feature, grapheme, and letter identification

<badge color="info">Operations 005–009</badge>

This group prepares written input for orthographic word recognition.

### IRA-OP-005 — Extract Visual Features

**Inputs**
- Normalized visual input.

**Processing**

Identify visual properties such as:
- Lines.
- Curves.
- Intersections.
- Endpoints.
- Orientation.
- Closed shapes.
- Relative positions.

For example, a written letter can be represented through a combination of geometrical features.

**Mathematical representation**

\[
F=\phi(X_v)
\]

Where \(\phi\) is a visual feature-extraction function.

**Output:** Visual feature vectors.

**Execution:** Parallel.

### IRA-OP-006 — Detect Graphemic Features

**Inputs**
- Visual feature vectors.

**Processing**

1. Group relevant visual features.
2. Identify candidate character shapes.
3. Estimate their graphemic identities.
4. Preserve competing character hypotheses when the input is ambiguous.

**Mathematical representation**

\[
P(g_i\mid F_i)
\]

Where \(g_i\) represents a possible grapheme.

**Output:** Grapheme hypotheses and confidence values.

**Execution:** Parallel.

### IRA-OP-007 — Activate Letter Identity Units

**Inputs**
- Grapheme hypotheses.

**Processing**

Activate possible letter identities.

For an ambiguous character, several letter units may initially receive activation.

**Mathematical representation**

\[
A(l_i)=f\left(\sum_j w_{ji}F_j+b_i\right)
\]

Where:
- \(F_j\): visual features.
- \(w_{ji}\): feature-to-letter connection weights.
- \(b_i\): bias.
- \(f\): activation function.

**Output:** Activated letter representations.

**Execution:** Parallel.

### IRA-OP-008 — Encode Letter Position

**Inputs**
- Letter identities.
- Spatial positions.

**Processing**

Associate each letter with its position in the written sequence.

For example:

\[
CAT\rightarrow
\{(C,1),(A,2),(T,3)\}
\]

Position is important because the same letters arranged differently can represent different words.

**Mathematical representation**

\[
R_o=\{(l_i,p_i)\}_{i=1}^{n}
\]

**Output:** Position-sensitive orthographic representation.

**Execution:** Parallel.

### IRA-OP-009 — Segment and Buffer Grapheme Sequences

**Inputs**
- Position-sensitive letter representations.

**Processing**

1. Organize individual letters into an ordered sequence.
2. Identify multiletter graphemes where appropriate.
3. Preserve their relative positions.
4. Store the resulting representation in the orthographic processing buffer.

Example:

\[
S H I P
\]

may be represented as:

\[
[SH][I][P]
\]

when the language's grapheme system treats SH as a single unit.

**Output:** Ordered grapheme sequence.

**Execution:** Sequential after initial feature extraction.

# 4. Operation group C — Interactive Activation and Orthographic Lexical Identification

<badge color="info">Operations 010–019</badge>

This group implements the core computational principles of the Interactive-Activation model and the orthographic lexicon.

The original Interactive-Activation model uses feature, letter, and word levels. Processing is parallel and interactive, with excitatory and inhibitory connections. <Cite refs={["turn556646search77","turn556646search81"]}/>

### IRA-OP-010 — Initialize Interactive Activation Network

**Inputs**
- Grapheme sequence.
- Available letter and word representations.

**Processing**

Initialize three processing levels:

1. Visual feature units.
2. Letter units.
3. Word units.

**Output:** Initialized interactive activation network.

**Execution:** Parallel.

### IRA-OP-011 — Propagate Bottom-Up Feature Activation

**Inputs**
- Activated visual features.

**Processing**

Propagate activation from visual features to compatible letter units.

Matching features strengthen their corresponding letter hypotheses.

**Mathematical representation**

\[
I_i^{bottom}=\sum_j w_{ji}a_j
\]

**Output:** Letter activation contributions.

**Execution:** Parallel.

### IRA-OP-012 — Perform Letter-Level Competition

**Inputs**
- Activated letter hypotheses.

**Processing**

1. Compare alternative letter hypotheses.
2. Increase support for compatible letters.
3. Inhibit incompatible letters occupying the same position.
4. Preserve uncertainty where necessary.

**Mathematical representation**

\[
\frac{da_i}{dt}
=
f(I_i)-\lambda a_i-\sum_{j\ne i}\gamma_{ij}a_j
\]

Here, \(\gamma_{ij}\) represents lateral inhibitory influence.

**Output:** Updated letter activation.

**Execution:** Recurrent.

### IRA-OP-013 — Propagate Letter Activation to Word Units

**Inputs**
- Position-sensitive letter activation.

**Processing**

Activate word units compatible with the detected letters and their positions.

For example, the pattern:

\[
C-A-T
\]

can activate the candidate CAT.

**Mathematical representation**

\[
I_k^{word}=\sum_i w_{ik}a_i
\]

**Output:** Activated lexical candidates.

**Execution:** Parallel.

### IRA-OP-014 — Perform Top-Down Word-to-Letter Feedback

**Inputs**
- Activated word candidates.

**Processing**

Send activation from plausible word units back to compatible letter units.

This helps resolve ambiguous visual features.

**Mathematical representation**

\[
I_i^{top}=\sum_k v_{ki}a_k^{word}
\]

**Output:** Updated letter activation.

**Execution:** Recurrent.

### IRA-OP-015 — Perform Word-Level Lateral Inhibition

**Inputs**
- Competing word candidates.

**Processing**

1. Compare candidates.
2. Increase competition between incompatible candidates.
3. Reduce activation of less-supported alternatives.
4. Maintain competing hypotheses until sufficient evidence accumulates.

**Mathematical representation**

\[
\frac{da_k}{dt}
=
f(I_k)-\lambda a_k
-\sum_{m\ne k}\gamma_{km}a_m
\]

**Output:** Competitive word activation.

**Execution:** Recurrent.

### IRA-OP-016 — Integrate Contextual Bias Into Lexical Activation

**Inputs**
- Word candidates.
- Previously recognized words.
- Sentence context.

**Processing**

Estimate how compatible each candidate is with the current linguistic context.

**Mathematical representation**

\[
S(w)=S_{orth}(w)+\alpha S_{context}(w)
\]

Where \(\alpha\) controls the computational influence of context.

**Output:** Context-adjusted lexical candidate scores.

**Execution:** Recurrent or parallel.

### IRA-OP-017 — Settle Interactive Activation

**Inputs**
- Feature activation.
- Letter activation.
- Word activation.
- Contextual activation.

**Processing**

Repeat activation propagation and competition until:
- Activation stabilizes.
- A confidence threshold is reached.
- A maximum processing interval is reached.

**Mathematical representation**

\[
\Delta A(t)=A(t+1)-A(t)
\]

Stopping condition:

\[
\|\Delta A(t)\|<\epsilon
\]

**Output:** Stabilized lexical hypotheses.

**Execution:** Recurrent.

### IRA-OP-018 — Search the Orthographic Lexicon

**Inputs**
- Stabilized orthographic representation.
- Candidate word hypotheses.

**Processing**

Compare the input against stored orthographic representations.

Each lexical entry may contain:

- Word spelling.
- Word identity.
- Frequency.
- Orthographic neighbors.
- Phonological representation.
- Semantic connections.
- Morphological information.

**Mathematical representation**

An illustrative matching score is:

\[
M(w)=
\sum_i \omega_i\,match(g_i,w)
\]

The matching operation can incorporate similarity, position, and spelling information.

**Output:** Matched orthographic lexical entries.

**Execution:** Parallel.

### IRA-OP-019 — Identify Lexical Word

**Inputs**
- Matched lexical entries.
- Candidate confidence values.
- Contextual scores.

**Processing**

Determine which lexical identity best explains the written input.

**Mathematical representation**

\[
P(w\mid X,C)=
\frac{e^{\beta S(w)}}{
\sum_j e^{\beta S(w_j)}
}
\]

**Output:**

- Selected word identity.
- Alternative candidates.
- Lexical confidence.

**Execution:** Conditional decision following candidate competition.

# 5. Operation group D — Dual-Route Reading Architecture

<badge color="info">Operations 020–030</badge>

The Dual-Route Cascaded model distinguishes lexical and nonlexical reading pathways. A central feature of the model is that processing can cascade between modules without requiring each earlier module to finish completely. Its implemented architecture includes lexical nonsemantic processing and grapheme-to-phoneme conversion. <Cite refs={["turn556646search1","turn556646search6"]}/>

### IRA-OP-020 — Dispatch Information to Reading Routes

**Inputs**
- Identified or partially identified orthographic representation.

**Processing**

Distribute processing information to two concurrent pathways:

**Route A: Lexical route**
- Uses stored word representations.

**Route B: Nonlexical route**
- Uses grapheme-to-phoneme correspondences.

**Output:** Two active processing streams.

**Execution:** Parallel.

### IRA-OP-021 — Match the Complete Word in the Lexical Route

**Inputs**
- Orthographic representation.
- Orthographic lexicon.

**Processing**

Search for a stored representation matching the input word.

This route is especially useful for familiar and irregularly spelled words.

**Mathematical representation**

\[
S_L(w)=Similarity(O_{input},O_w)
\]

**Output:** Lexical match candidates.

**Execution:** Parallel.

### IRA-OP-022 — Retrieve Stored Phonological Representation

**Inputs**
- Lexical match candidates.

**Processing**

Retrieve the associated phonological representation of each matched word.

For example:

\[
CAT\rightarrow /kæt/
\]

**Mathematical representation**

\[
P_{lex}=\operatorname{Lookup}(w,\text{phonology})
\]

**Output:** Lexically retrieved pronunciation.

**Execution:** Cascaded.

### IRA-OP-023 — Retrieve Semantic Information From Lexical Representation

**Inputs**
- Identified lexical entry.

**Processing**

Activate its associated meaning representation.

For example:

\[
CAT\rightarrow
\{\text{animal},\text{feline},\text{domestic}\}
\]

**Output:** Candidate semantic representation.

**Execution:** Parallel.

**Implementation note:** This is a shared semantic interface for the master architecture. It should not be confused with a claim that the canonical 2001 DRC implementation fully implemented its proposed lexical-semantic route.

### IRA-OP-024 — Segment Orthographic Input for Nonlexical Conversion

**Inputs**
- Ordered grapheme sequence.

**Processing**

Divide the word into units suitable for grapheme-to-phoneme conversion.

**Output:** Grapheme units and their positions.

**Execution:** Parallel.

### IRA-OP-025 — Retrieve Grapheme-to-Phoneme Correspondence Rules

**Inputs**
- Grapheme units.
- Language-specific pronunciation rules.

**Processing**

Identify possible phoneme mappings.

For example:

\[
G\rightarrow /g/
\]

\[
SH\rightarrow /\ʃ/
\]

Mappings must account for language-specific spelling conventions and irregularities.

**Output:** Candidate correspondence rules.

**Execution:** Parallel.

### IRA-OP-026 — Align Graphemes With Phonemes

**Inputs**
- Grapheme sequence.
- Correspondence rules.

**Processing**

Determine the relationships between written units and their possible sound representations.

A mapping does not necessarily require one letter per phoneme.

**Mathematical representation**

\[
A_{gp}=\{(g_i,p_j)\}
\]

**Output:** Grapheme-phoneme alignment.

**Execution:** Parallel.

### IRA-OP-027 — Generate Phonological Candidates

**Inputs**
- Grapheme-phoneme alignments.

**Processing**

1. Apply compatible conversion rules.
2. Generate possible phoneme sequences.
3. Preserve alternative mappings when ambiguity exists.
4. Assign confidence to each sequence.

**Mathematical representation**

\[
P(P\mid G)=
\prod_i P(p_i\mid g_i,\text{context}_i)
\]

This product is a simplified approximation; practical implementations should account for dependencies between neighboring mappings.

**Output:** Generated phonological candidates.

**Execution:** Parallel.

### IRA-OP-028 — Apply Phonological and Orthographic Constraints

**Inputs**
- Generated phoneme sequences.
- Language-specific phonological constraints.

**Processing**

Evaluate:
- Phoneme ordering.
- Permitted sound combinations.
- Syllable structures.
- Stress patterns.
- Pronunciation conventions.

**Mathematical representation**

\[
S(P)=S_{mapping}(P)+S_{phonotactic}(P)
\]

**Output:** Constrained phonological candidates.

**Execution:** Parallel.

### IRA-OP-029 — Integrate Lexical and Nonlexical Route Evidence

**Inputs**
- Lexical pronunciation candidates.
- GPC pronunciation candidates.
- Associated confidence information.

**Processing**

Compare the evidence generated by both routes.

The system must not blindly select one route in every situation.

For example:
- Familiar irregular words may receive strong support from the lexical route.
- Unfamiliar pronounceable words may receive support from the nonlexical route.
- Conflicting candidates remain available for further evaluation.

**Mathematical representation**

\[
S(P)=
\alpha S_L(P)+
\beta S_{GPC}(P)
\]

This is an architectural scoring approximation, not a literal equation asserted by the DRC model.

**Output:** Integrated pronunciation hypotheses.

**Execution:** Parallel followed by competitive evaluation.

### IRA-OP-030 — Select Task-Appropriate Reading Representation

**Inputs**
- Lexical identity.
- Phonological hypotheses.
- Semantic hypotheses.
- Reading task.

**Processing**

Determine whether the current task requires:
- Lexical recognition only.
- Silent comprehension.
- Phonological output.
- Both meaning and pronunciation.

**Output:** Task-specific representation for subsequent processing.

**Execution:** Conditional.

# 6. Operation group E — Connectionist Spelling-to-Sound-to-Meaning Architecture

<badge color="info">Operations 031–038</badge>

This group implements distributed representations and learned mappings between orthography, phonology, and semantics.

The connectionist approach differs from a strict dual-route implementation: it can learn spelling-to-pronunciation mappings through distributed connection weights, including irregular words and novel pronounceable items. The connectionist triangle architecture also accounts for the contribution of semantic processing to pronunciation. <Cite refs={["turn204905search0","turn204905search46"]}/>

### IRA-OP-031 — Encode Distributed Orthographic Representation

**Inputs**
- Recognized graphemes.
- Letter positions.

**Processing**

Transform the orthographic input into a distributed activation pattern.

Instead of representing a complete word using only one dedicated identifier, distribute its information across multiple processing units.

**Mathematical representation**

\[
O=[o_1,o_2,\ldots,o_n]
\]

**Output:** Distributed orthographic vector.

**Execution:** Parallel.

### IRA-OP-032 — Compute Hidden-Layer Activation

**Inputs**
- Distributed orthographic vector.
- Learned connection weights.

**Processing**

Propagate orthographic information through intermediate processing units.

These hidden units learn statistical relationships between spelling, pronunciation, and meaning.

**Mathematical representation**

\[
H=\phi(W_{OH}O+b_H)
\]

Where:
- \(O\): orthographic input.
- \(W_{OH}\): orthography-to-hidden weights.
- \(H\): hidden activation.
- \(\phi\): activation function.

**Output:** Hidden distributed representation.

**Execution:** Parallel.

### IRA-OP-033 — Compute Orthography-to-Phonology Mapping

**Inputs**
- Hidden activation.
- Phonological connection weights.

**Processing**

Generate pronunciation candidates directly from distributed spelling information.

**Mathematical representation**

\[
P_{OP}=\phi(W_{HP}H+b_P)
\]

**Output:** Phonological representation generated from orthography.

**Execution:** Parallel.

### IRA-OP-034 — Compute Orthography-to-Semantics Mapping

**Inputs**
- Hidden activation.
- Semantic connection weights.

**Processing**

Activate potential meanings associated with the written input.

**Mathematical representation**

\[
M_{OS}=\phi(W_{HM}H+b_M)
\]

**Output:** Semantic activation generated from orthography.

**Execution:** Parallel.

### IRA-OP-035 — Compute Semantics-to-Phonology Mapping

**Inputs**
- Semantic activation.
- Phonological connection weights.

**Processing**

Use activated semantic representations to contribute to pronunciation generation.

This is particularly relevant when the relationship between spelling and pronunciation is irregular.

**Mathematical representation**

\[
P_{SP}=\phi(W_{MP}M+b_{SP})
\]

**Output:** Semantically mediated phonological representation.

**Execution:** Parallel.

### IRA-OP-036 — Perform Distributed Activation Settling

**Inputs**
- Orthographic activation.
- Phonological activation.
- Semantic activation.
- Connection weights.

**Processing**

Allow the distributed representations to converge toward mutually compatible states.

The network updates its activation repeatedly until a stable representation is reached.

**Mathematical representation**

\[
H_{t+1}=f(H_t,O,P,M)
\]

Stopping criterion:

\[
\|H_{t+1}-H_t\|<\epsilon
\]

**Output:** Settled distributed representation.

**Execution:** Recurrent.

### IRA-OP-037 — Read Out Connectionist Predictions

**Inputs**
- Settled distributed representation.

**Processing**

Extract:
- Most strongly supported phonological candidate.
- Most strongly supported semantic candidate.
- Confidence of each output.

**Mathematical representation**

\[
P(p_i)=
\frac{e^{z_i}}{\sum_j e^{z_j}}
\]

The same type of readout can be applied to semantic units using an appropriate output activation.

**Output:** Phonological and semantic predictions.

**Execution:** Conditional readout.

### IRA-OP-038 — Update Connectionist Learning Weights

**Inputs**
- Predicted outputs.
- Correct or supervised target representations.
- Learning error.

**Processing**

During model training, modify connection weights to improve future mapping performance.

**Mathematical representation**

\[
W_{t+1}=W_t-\eta\nabla_W L
\]

Where:
- \(W\): connection weights.
- \(\eta\): learning rate.
- \(L\): prediction loss.

**Output:** Updated connection weights.

**Execution:** Learning/training operation, not mandatory during every reading transaction.

# 7. Operation group F — Auditory Speech Recognition: TRACE, Cohort, and Shortlist B

<badge color="info">Operations 039–051</badge>

This group is important because the previous algorithm includes three theories specifically concerned with spoken-word recognition.

These models must be integrated carefully:

- **TRACE:** interactive activation between speech features, phonemes, and words.
- **Cohort:** formation and progressive restriction of candidate words based on the incoming speech.
- **Shortlist B:** Bayesian evaluation of competing word and segmentation hypotheses.

TRACE uses interactive activation, whereas Shortlist B explicitly uses Bayesian inference and a feedforward architecture. They should therefore be implemented as different computational mechanisms, not combined into one artificial mechanism. <Cite refs={["turn556646search0","turn556646search2","turn556646search3"]}/>

## F1. TRACE operations

### IRA-OP-039 — Extract Temporal Acoustic Information

**Inputs**
- Auditory waveform.

**Processing**

1. Divide incoming speech into overlapping time frames.
2. Extract acoustic characteristics.
3. Preserve temporal relationships.
4. Maintain information about changing acoustic cues.

**Mathematical representation**

\[
X_a=\{x(t_1),x(t_2),\ldots,x(t_n)\}
\]

**Output:** Temporal acoustic feature sequence.

**Execution:** Parallel across time frames.

### IRA-OP-040 — Activate TRACE Feature Units

**Inputs**
- Acoustic feature sequence.

**Processing**

Activate speech-feature units corresponding to detected acoustic properties.

Examples include:
- Voicing characteristics.
- Frication.
- Nasality.
- Place of articulation.
- Manner of articulation.

**Mathematical representation**

\[
A_f(t)=f(W_fX_a(t))
\]

**Output:** Speech-feature activation.

**Execution:** Parallel.

### IRA-OP-041 — Activate TRACE Phoneme Units

**Inputs**
- Speech-feature activation.

**Processing**

Combine speech features to activate phoneme hypotheses.

For example, acoustic evidence can support competing phoneme identities until more information becomes available.

**Mathematical representation**

\[
A_p(t)=f(W_{fp}A_f(t))
\]

**Output:** Phoneme activation patterns.

**Execution:** Parallel and recurrent.

### IRA-OP-042 — Activate TRACE Word Units and Feedback

**Inputs**
- Phoneme activation.
- Stored word representations.

**Processing**

1. Activate words compatible with the current phoneme sequence.
2. Allow word units to reinforce compatible phonemes.
3. Inhibit incompatible alternatives.
4. Update the network while additional speech information arrives.

**Mathematical representation**

\[
\Delta A_p=
I_{bottom-up}+I_{top-down}-I_{inhibition}
\]

**Output:** Interactive phoneme-word activation.

**Execution:** Recurrent.

## F2. Cohort operations

### IRA-OP-043 — Initialize Cohort Candidate Set

**Inputs**
- Initial speech phonemes or phonological evidence.

**Processing**

Generate a set of word candidates compatible with the initial part of the speech signal.

Example:

An initial sound sequence may activate several words beginning with that sequence.

**Mathematical representation**

\[
C_0=
\{w\in Lexicon:
w\text{ matches initial input}\}
\]

**Output:** Initial cohort.

**Execution:** Parallel.

### IRA-OP-044 — Update and Restrict the Cohort

**Inputs**
- Current cohort.
- Newly received phonological evidence.

**Processing**

1. Compare incoming evidence against current candidates.
2. Eliminate incompatible candidates.
3. Preserve candidates that remain compatible.
4. Repeat as additional speech becomes available.

**Mathematical representation**

\[
C_t=
\{w\in C_{t-1}:
Compatible(w,X_{1:t})\}
\]

**Output:** Updated cohort.

**Execution:** Recurrent.

### IRA-OP-045 — Select the Spoken Lexical Candidate

**Inputs**
- Updated cohort.
- Lexical and contextual evidence.

**Processing**

1. Compare surviving candidates.
2. Evaluate their compatibility with the input.
3. Determine whether sufficient evidence exists for selection.
4. Preserve ambiguity when necessary.

**Mathematical representation**

\[
w^*=
\arg\max_{w\in C_t}S(w)
\]

**Output:** Selected spoken-word hypothesis.

**Execution:** Conditional.

The exact influence of contextual information on candidate access and selection depends on which version of the Cohort account is being implemented.

## F3. Shortlist B operations

### IRA-OP-046 — Generate Continuous-Speech Segmentation Hypotheses

**Inputs**
- Speech input.
- Phoneme probability distributions over time.

**Processing**

Generate alternative word-boundary and lexical segmentation hypotheses.

The incoming signal is not necessarily supplied as a sequence of perfectly identified phonemes. Instead, phonetic uncertainty is preserved.

**Mathematical representation**

\[
X=\{P_t(\phi_1),P_t(\phi_2),\ldots\}
\]

**Output:** Alternative segmentation hypotheses.

**Execution:** Parallel.

### IRA-OP-047 — Calculate Word-Input Likelihood

**Inputs**
- Segmentation hypotheses.
- Acoustic/phonetic evidence.
- Candidate words.

**Processing**

Estimate how likely the incoming evidence is under each lexical candidate.

**Mathematical representation**

\[
P(X\mid w)
\]

**Output:** Likelihood scores.

**Execution:** Parallel.

### IRA-OP-048 — Calculate Lexical Prior Probability

**Inputs**
- Candidate words.
- Lexical frequency information.
- Relevant word-sequence information.

**Processing**

Estimate the prior plausibility of each word candidate before considering its current acoustic fit.

**Mathematical representation**

\[
P(w)
\]

For sequences of words, a language model can supply conditional probabilities:

\[
P(w_i\mid w_1,\ldots,w_{i-1})
\]

**Output:** Lexical prior scores.

**Execution:** Parallel.

### IRA-OP-049 — Calculate Bayesian Posterior Probability

**Inputs**
- Candidate likelihood.
- Lexical prior.

**Processing**

Combine the evidence using Bayesian inference.

**Mathematical representation**

\[
P(w\mid X)=
\frac{P(X\mid w)P(w)}{P(X)}
\]

**Output:** Posterior probability for each candidate.

**Execution:** Parallel.

### IRA-OP-050 — Perform Bayesian Word and Segmentation Competition

**Inputs**
- Posterior probabilities.
- Alternative segmentation hypotheses.

**Processing**

Evaluate competing word sequences and segmentation possibilities.

Select the hypothesis that gives the strongest overall explanation of the input evidence.

**Mathematical representation**

\[
W^*=
\arg\max_W P(W\mid X)
\]

Or equivalently:

\[
W^*=
\arg\max_W
\left[
\log P(X\mid W)+\log P(W)
\right]
\]

**Output:** Best-supported speech segmentation and lexical sequence.

**Execution:** Competitive Bayesian inference.

### IRA-OP-051 — Commit Spoken-Word Recognition Result

**Inputs**
- TRACE hypotheses, when that profile is selected.
- Cohort hypotheses, when that profile is selected.
- Shortlist B hypotheses, when that profile is selected.

**Processing**

The master controller:

1. Determines which auditory recognition model is configured.
2. Receives its candidate output.
3. Checks confidence and unresolved ambiguity.
4. Produces a recognized lexical representation.
5. Passes it to the shared lexical-semantic processing interface.

**Output:** Recognized spoken lexical items.

**Execution:** Conditional.

<box border radius="lg" padding={3} gap={2}>
  **Important architectural rule**

  The three spoken-word models have separate inference mechanisms. OP-051 is a common interface, not a mathematical merger of all three models.

# 8. Operation group G — Lexical-semantic integration and language comprehension

<badge color="info">Operations 052–057</badge>

At this point, visual and auditory processing can supply recognized lexical representations to shared language-comprehension operations.

### IRA-OP-052 — Consolidate Lexical Identity

**Inputs**
- Recognized orthographic identity.
- Recognized spoken identity, when applicable.
- Alternative lexical hypotheses.

**Processing**

Establish a common lexical representation for the recognized item.

Associate the word's:
- Orthographic form.
- Phonological form.
- Lexical identity.
- Morphological information.
- Access confidence.

**Mathematical representation**

\[
L_i=\{O_i,P_i,I_i,Morph_i\}
\]

**Output:** Consolidated lexical representation.

**Execution:** Parallel.

### IRA-OP-053 — Activate Semantic Representations

**Inputs**
- Consolidated lexical representation.
- Semantic associations.

**Processing**

Activate potential meanings associated with the word.

For example:

\[
BANK\rightarrow
\{
\text{financial institution},
\text{river bank}
\}
\]

**Mathematical representation**

\[
A(m_i)=f(W_{LM}L_i)
\]

**Output:** Semantic candidate activations.

**Execution:** Parallel.

### IRA-OP-054 — Integrate Sentence Context

**Inputs**
- Semantic candidate activations.
- Previously identified words.
- Current sentence information.

**Processing**

Evaluate how each semantic candidate fits the sentence.

**Mathematical representation**

\[
P(m\mid w,C)
\propto P(w\mid m,C)P(m\mid C)
\]

This expression represents a probabilistic approximation of contextual semantic inference.

**Output:** Context-sensitive semantic hypotheses.

**Execution:** Parallel.

### IRA-OP-055 — Resolve Semantic Ambiguity

**Inputs**
- Semantic hypotheses.
- Contextual compatibility.
- Lexical evidence.

**Processing**

1. Compare alternative meanings.
2. Evaluate their contextual support.
3. Reduce activation of incompatible interpretations.
4. Select a sufficiently supported interpretation.
5. Maintain alternatives when the sentence remains ambiguous.

**Mathematical representation**

\[
m^*=\arg\max_m P(m\mid w,C)
\]

**Output:** Selected or unresolved semantic representation.

**Execution:** Competitive and conditional.

### IRA-OP-056 — Integrate Words Into Syntactic Structure

**Inputs**
- Recognized lexical items.
- Grammatical information.
- Word order.
- Semantic constraints.

**Processing**

Build relationships between words.

Examples of syntactic relations:
- Subject.
- Object.
- Verb.
- Modifier.
- Phrase membership.
- Dependency relations.

**Mathematical representation**

Represent a sentence as a graph:

\[
G=(V,E)
\]

Where:
- \(V\): word or phrase nodes.
- \(E\): grammatical relationships.

An implementation may additionally use probabilistic parsing:

\[
T^*=\arg\max_T P(T\mid W)
\]

**Output:** Syntactic representation.

**Execution:** Incremental and recurrent.

### IRA-OP-057 — Update Working Memory and Sentence Meaning

**Inputs**
- Syntactic structure.
- Semantic representations.
- Previously processed sentence information.

**Processing**

1. Maintain relevant words and phrases.
2. Connect new information with existing context.
3. Resolve references where possible.
4. Update sentence-level meaning.
5. Preserve unresolved information for subsequent processing.

**Mathematical representation**

\[
C_{t+1}=F(C_t,L_t,M_t,T_t)
\]

Where \(C_t\) is the current contextual state.

**Output:** Updated sentence/discourse representation.

**Execution:** Recurrent and incremental.

# 9. Operation group H — Reading output, attention, and monitoring

<badge color="info">Operations 058–062</badge>

These operations produce the appropriate response and allow the system to continue reading.

### IRA-OP-058 — Construct Task-Specific Reading Result

**Inputs**
- Lexical identity.
- Phonological representation.
- Semantic representation.
- Syntactic structure.
- Task configuration.

**Processing**

Construct the result required by the reading task.

Possible outputs:

1. Recognized word.
2. Word pronunciation.
3. Word meaning.
4. Sentence meaning.
5. Combined linguistic representation.

**Mathematical representation**

\[
R=F(L,P,M,T)
\]

**Output:** Task-specific reading result.

**Execution:** Conditional.

### IRA-OP-059 — Prepare Phonological Output

**Inputs**
- Selected phonological representation.
- Pronunciation plan.

**Processing**

Prepare the recognized phonological sequence for possible speech production.

For example:

\[
P=[p_1,p_2,\ldots,p_n]
\]

Organize:
- Phoneme order.
- Syllable structure.
- Stress.
- Timing information.
- Relevant pronunciation constraints.

**Output:** Phonological production plan.

**Execution:** Conditional, when pronunciation is required.

### IRA-OP-060 — Produce Overt Speech or Silent Reading Output

**Inputs**
- Task-specific reading result.
- Phonological production plan, where applicable.

**Processing**

For overt reading:
- Prepare articulatory instructions.
- Coordinate the phonological sequence with speech production.

For silent reading:
- Return the recognized word and/or integrated meaning without requiring overt articulation.

**Output:** Spoken pronunciation or silent comprehension result.

**Execution:** Conditional.

### IRA-OP-061 — Direct Attention to the Next Reading Unit

**Inputs**
- Current processing completion.
- Remaining input.
- Attention and working-memory state.

**Processing**

1. Determine whether more text remains.
2. Select the next reading unit.
3. Advance the reading position.
4. Preserve relevant previous context.
5. Supply the next unit to the appropriate input-processing operations.

For visual reading, this operation may include attention shifts and eye-movement planning. It should not assume that each word is necessarily processed in a strictly serial manner.

**Mathematical representation**

\[
q_{t+1}=\operatorname{NextUnit}(q_t,X)
\]

Where \(q_t\) is the current reading position.

**Output:** Next processing target or end-of-input signal.

**Execution:** Conditional and recurrent.

### IRA-OP-062 — Monitor Processing and Initiate Reanalysis

**Inputs**
- Lexical results.
- Phonological results.
- Semantic results.
- Syntactic representation.
- Confidence values.

**Processing**

Check for:
- Low-confidence word identification.
- Incompatible spelling and pronunciation evidence.
- Semantic inconsistencies.
- Syntactic inconsistencies.
- Unresolved ambiguities.
- Possible recognition errors.

If an error is detected:

1. Identify the affected representation.
2. Return the relevant information to an appropriate earlier operation.
3. Recalculate the affected hypotheses.
4. Update the reading result.

**Mathematical representation**

\[
E=1-\operatorname{Confidence}(R)
\]

Reanalysis condition:

\[
E>\theta_E
\]

**Output:** Validated reading result or reanalysis request.

**Execution:** Recurrent and conditional.

# 13. Registry-wide execution rules

These rules apply to every operation.

**Rule 1 — Preserve uncertainty.**

An operation must not discard alternative hypotheses prematurely.

**Rule 2 — Preserve representation separation.**

Orthographic, phonological, lexical, and semantic representations must remain independently identifiable, even when they interact.

**Rule 3 — Support parallel processing.**

Operations that do not depend on one another should be allowed to execute concurrently.

**Rule 4 — Support recurrent processing.**

Interactive Activation, distributed settling, candidate competition, and reanalysis must permit repeated updates.

**Rule 5 — Preserve model-specific behavior.**

The Bayesian operations of Shortlist B must not be replaced with TRACE-style activation equations. Similarly, the Dual-Route and Connectionist pathways must preserve their distinct assumptions.

**Rule 6 — Separate online recognition from learning.**

Operation 038 updates connection weights during training. It must not automatically modify long-term learning parameters every time a word is read.

**Rule 7 — Make operations independently testable.**

Each operation must have its own input validation, output contract, and computational tests.

The registry should now be treated as the baseline specification for the Integrated Reading Algorithm.

The next software-development step should be to translate these 62 operations into a formal Python operation registry, where every operation has:

1. A permanent operation ID.
2. A Python implementation.
3. A typed input contract.
4. A typed output contract.
5. Its mathematical computation.
6. Explicit dependencies.
7. Unit tests.
8. Integration tests.
9. A traceable execution record.

**One especially important distinction for the eventual neural implementation:** this registry describes computational functions inspired by cognitive models. Reproducing the biological mechanisms underlying those functions will require a separate neural implementation and validation layer; successful execution of these 62 operations alone would not demonstrate that the biological reading mechanisms have been reproduced.

That distinction will prevent the software implementation from confusing *functional similarity* with *biological equivalence*.
