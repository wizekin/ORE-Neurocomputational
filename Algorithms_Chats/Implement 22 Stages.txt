## 2. Mathematical and biological implementation

The mathematical implementation includes:

- Temporal association: \(A_{ij}=e^{-\Delta t/\tau}\)
- Cosine similarity and feature normalization.
- Softmax probability distributions.
- Cross-modal contrastive loss.
- Weighted multimodal integration.
- Semantic graph activation spreading.
- Prediction residuals and uncertainty.
- Attention allocation.
- Memory retrieval and decay.
- Hebbian-style learning.
- Temporal-difference learning.
- Learner performance and adaptive activity selection.

The biological reference contains 13 interacting functional populations, including sensory spokes, an ATL transmodal hub, semantic-control, predictive, hippocampal-memory, plasticity and language-output populations.

It uses a current-based leaky integrate-and-fire model. This is a computational biological analogy, not a claim of reproducing exact human neural activity.

## 3. SQLite annotations

This uses your existing `ore_logger` system rather than creating a separate logging framework.

Two important functions have been added:

`register_grounded_annotations()`

Automatically indexes Python classes and functions, including their docstrings, signatures, source locations and hashes, into the SQLite annotations catalogue.

`record_grounded_result(result)`

Persists the mathematical operation records and all 22 stage traces into the logger's SQLite database.

Default database:

`ore_logs/ore_logger.sqlite3`

**Important:** The code and SQLite integration are implemented, and the tests use temporary databases. The persistent database in your repository has not yet been populated by running the application itself.
