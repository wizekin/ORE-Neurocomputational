## Algorithm 2 — Lexical access

<badge color="info">Next implementation</badge>

The second algorithm is **Point 2: Retrieve word-level lexical entries and meanings from recognized word forms**.

Unlike Algorithm 1, which identifies possible phonetic or written forms, Algorithm 2 must connect those forms to stored lexical knowledge.

Its central task is to transform something like:

`c-a-t` or a spoken sequence /kæt/

into competing lexical candidates containing information such as:

- Canonical word identity.
- Spoken and written forms.
- Word frequency and familiarity.
- Morphological structure.
- Grammatical category and features.
- Semantic features and possible senses.
- Confidence and unresolved ambiguity.

The algorithm must support both auditory and visual access without assuming that they use identical initial representations.

**Important boundary:** This stage retrieves word-level meanings and lexical properties. It does not yet construct sentence grammar or combine multiple words into a sentence-level proposition.

## Algorithm 3 — Syntactic parsing

<badge color="success">Implemented in GitHub PR #30</badge>

I created [PR #30 — Implement language comprehension Point 3](https://github.com/wizekin/ORE-Neurocomputational/pull/30), based on the Point 2 branch.

The implementation reuses ORE’s existing nine-stage, 58-operation syntax engine and adds a 12-step Point 3 layer. It accepts ordered lexical records from Point 2, preserves part-of-speech alternatives, builds phrase and dependency structures, checks supplied grammatical features, tracks unresolved dependencies, and records how the parse changes as each word arrives.

The new code, focused tests, documentation, package exports, and SQLite annotation registration are included in the PR. The annotation registration writes into the existing `ore_logger.annotations` database table; it does not introduce a separate annotation database.

### The 12 implemented steps

1. Receive each lexical item and align it with the current sentence position.
2. Estimate possible grammatical categories, retaining ambiguity.
3. Predict likely next categories and calculate syntactic surprisal.
4. Build and extend nested phrase constituents.
5. Identify phrase heads and grammatical dependencies.
6. Check agreement using supplied number, person, gender, case, and noun-class features.
7. Combine word order, function words, inflection, punctuation, and supplied speech-prosody cues.
8. Maintain unresolved and long-distance dependencies.
9. Rank competing constituency structures without forcing an early winner.
10. Detect structural conflicts and unexpected grammatical evidence.
11. Reanalyse earlier category or attachment decisions when new words challenge them.
12. Consolidate the grammatical structure for the next semantic-composition stage.

### Mathematical and biological implementation

The functional implementation uses category scoring and softmax normalization:

\[
P(c\mid E)=\frac{e^{s_c/T}}{\sum_k e^{s_k/T}}
\]

It calculates syntactic surprisal:

\[
Surprisal_i=-\log_2 P(c_i\mid S_{i-1})
\]

It also applies soft penalties to dependency scores when explicitly supplied grammatical features disagree:

\[
E_{\text{agreement}}=\sum_r \lambda_r\,mismatch_r
\]

\[
Score_{\text{updated}}=Score_{\text{previous}}-E_{\text{agreement}}
\]

The biological-reference track reuses ORE's nine-population, current-based LIF syntax network. It aggregates the 58 underlying syntax operations into the 12 Point 3 steps. The intermediate word-prefix parses run without LIF dynamics; the final parse runs the configured biological simulation once. This is a computational reference, not a measured or anatomically fitted model of the human brain.

### Important implementation boundaries

The adapter creates a parse snapshot for every growing word prefix and records category and dependency revisions. It uses repeated prefix parsing through the existing engine rather than a persistent, mutable parse forest. That is an explicit engineering approximation of incremental processing.

The existing grammar is English-oriented; assigning another language code does not automatically add that language's word order, case, agreement, or morphology rules. Agreement checks also depend on features actually supplied by the lexical input.

Point 3's public result does not pass on a completed sentence proposition or thematic-role interpretation. Those remain for later stages.
