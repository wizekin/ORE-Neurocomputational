## 1. Mathematical implementation

Each processing stage will have explicit inputs, outputs, state variables and mathematical operations.

| Stage | Computational operation | Purpose |
|---|---|---|
| Visual normalization | Contrast normalization, spatial filtering | Reduce visual variation |
| Feature extraction | Convolution, edge detection, feature maps | Detect visual letter features |
| Position encoding | Spatial coordinates and relative-position vectors | Preserve letter order |
| Orthographic encoding | Feature combination and sequence encoding | Represent letter strings |
| Familiarity detection | Similarity and probability scoring | Detect familiar patterns |
| Lexical competition | Parallel candidate activation and normalization | Resolve competing words |
| Prediction | Conditional probability estimation | Predict likely word forms |
| Error correction | Prediction minus observed evidence | Revise incorrect hypotheses |
| Semantic access | Associative activation | Retrieve meaning |
| Confidence | Posterior probability and uncertainty | Evaluate recognition reliability |

### 1.1 Visual feature extraction

Let the input image be:

\[
I(x,y)
\]

First, normalize its pixel intensities:

\[
I_n(x,y)=\frac{I(x,y)-\mu_I}{\sigma_I+\epsilon}
\]

Where:

- \(\mu_I\): average image intensity.
- \(\sigma_I\): image intensity standard deviation.
- \(\epsilon\): small numerical constant.

Then extract visual features using filters:

\[
F_k(x,y)=\sum_{u,v} I_n(x-u,y-v)K_k(u,v)
\]

Here, \(K_k\) represents a visual filter detecting features such as edges, orientations or curves.

The resulting feature maps provide information that subsequent stages can use to distinguish letters.

### 1.2 Letter-position representation

For a word containing \(n\) letters, represent each detected letter with:

\[
L_i=(f_i,p_i)
\]

Where \(f_i\) is its feature vector and \(p_i\) is its spatial position.

Relative position can be represented as:

\[
r_{ij}=p_j-p_i
\]

This matters because recognizing a word requires more than identifying which letters are present. Their order and relative positions are important.

### 1.3 Orthographic representation

Construct a representation of the entire letter sequence:

\[
O=(L_1,L_2,\ldots,L_n,R)
\]

Where \(R\) contains relationships between the letters, including position and neighboring-feature information.

The representation should tolerate reasonable variations in font, size and spacing without losing distinctions between different words.

### 1.4 Lexical candidate activation

For each candidate word \(w\), calculate its compatibility with the observed orthographic representation:

\[
S(w)=
\beta_1 S_{\text{features}}(w)
+\beta_2 S_{\text{position}}(w)
+\beta_3 S_{\text{sequence}}(w)
+\beta_4 S_{\text{frequency}}(w)
\]

Convert the scores into normalized probabilities:

\[
P(w\mid O)=
\frac{\exp(S(w)/T)}
{\sum_j \exp(S(w_j)/T)}
\]

Here, \(T\) controls the distribution's sharpness.

This allows multiple word candidates to remain active until enough evidence is available.

### 1.5 Predictive processing

The system also predicts what orthographic evidence it expects:

\[
\hat O=G(C)
\]

Where \(C\) represents the current contextual state.

Calculate prediction error:

\[
e=O-\hat O
\]

A precision-weighted error is:

\[
e_p=\Pi e
\]

Where \(\Pi\) represents confidence in the prediction.

The system can use this error to revise its candidate probabilities rather than immediately accepting its first interpretation.

**Important:** These equations define our computational model, not established literal equations for VWFA neurons.

We must not consider the implementation successful merely because it recognizes familiar words.

I recommend five experiments:

| Experiment | What it tests |
|---|---|
| E1 — Familiar words | Recognition of known letter sequences |
| E2 — Unfamiliar words | Generalization to unseen sequences |
| E3 — Visual variation | Recognition across fonts, sizes and spacing |
| E4 — Ambiguity | Competition between similar words |
| E5 — Predictive correction | Whether contextual predictions improve recognition without overriding visual evidence |

We will also run ablation experiments: disable individual modules and measure how much performance deteriorates.

### Acceptance criteria

The laboratory must demonstrate:

- Intermediate representations can be inspected.
- Recognition accuracy is measured on held-out data.
- Unfamiliar words are evaluated separately from familiar words.
- Prediction improves performance against an otherwise identical non-predictive baseline.
- Context cannot silently transform an incorrect visual observation into a supposedly correct one.
- Every mathematical operation has a documented implementation.
- Results are reproducible.

## 1. Mission and boundaries

ORE is a computational subsystem whose responsibility is to learn, construct, maintain and recognize representations of written forms.

Its central question is:

**How can a system transform visual evidence of written characters into stable, position-sensitive, reusable orthographic representations without relying exclusively on predefined word identities?**

ORE must distinguish three things:

- What it visually observes.
- What orthographic structure it has inferred.
- What it has learned about the statistical regularities of written forms.

These must remain separately inspectable.

### 1.1 Responsibilities

ORE owns:

1. Visual-feature-to-orthographic-feature transformation.
2. Character identity hypotheses.
3. Absolute and relative letter-position encoding.
4. Letter sequence and multi-letter pattern representations.
5. Learning of recurring orthographic patterns.
6. Invariance to selected visual variations.
7. Recognition and similarity calculations.
8. Confidence, uncertainty and competing interpretations.
9. Incremental updating from new visual examples.

### 1.2 Explicit exclusions

ORE v1.0 does not attempt to implement:

- Full visual object recognition.
- General language understanding.
- Sentence-level semantic interpretation.
- Complete phonological production.
- General contextual reasoning.
- A complete biological simulation of the VWFA.
- A complete brain-inspired reading system.

These belong to other components or later development stages.

### Important architectural decision

ORE now has three explicitly separated operating modes:

1. **LEARN:** Acquires and improves orthographic knowledge.
2. **RECOGNIZE:** Processes new visual input using the learned knowledge.
3. **INCREMENTAL_LEARN:** Updates existing knowledge under controlled conditions.

# ORE Stage C — Learn Visual and Character Representations

<row align="center" gap={2}>
  <badge color="success">Implemented</badge>

**Stage C (C1–C4) is implemented in Python.** It builds on the existing Stage A and Stage B implementations. I have not started Stage D.

The implementation is designed to give ORE its first trainable visual representation system: it can encode character patches, learn visual similarities, estimate grapheme identity when labels are available, and retain uncertainty when identity is unknown.

## 1. What Stage C implements

| Step | Algorithm | Implementation |
|---|---|---|
| C1 | Visual feature extraction | Grayscale normalization, image resizing and a trainable two-layer MLP encoder |
| C2 | Character identity estimation | Supervised grapheme classifier and explicit unknown-character handling |
| C3 | Visual invariance learning | Contrastive learning between different views of the same patch and examples of the same grapheme |
| C4 | Uncertainty preservation | Candidate distributions, entropy, unknown probability and visual-distance estimates |

### C1 — Visual representation

Each patch is transformed into a fixed-size numerical representation.

\[
P \rightarrow X \rightarrow h_1 \rightarrow z
\]

Where:

- \(P\): original grayscale patch.
- \(X\): resized and normalized visual input.
- \(h_1\): hidden visual representation.
- \(z\): learned feature vector.

The encoder uses trainable weights, rather than a predefined dictionary of character patterns.

### C2 — Grapheme identity

For supervised training:

\[
P(c\mid z)=\operatorname{softmax}(W_c z+b_c)
\]

The classifier learns only from eligible training labels generated by Stage B.

An important safeguard: characters in the script inventory that have not been observed during training are identified as unsupported, rather than being treated as impossible.

For unlabeled data, ORE learns visual features and clusters without pretending that a cluster represents a particular letter.

### C3 — Visual invariance

The system learns that two suitable visual variations of the same character patch should have similar representations.

One component of the learning objective is:

\[
L_{\text{contrastive}} =
yD^2+(1-y)\max(0,m-D)^2
\]

Where \(D\) is the distance between two representations, \(y\) indicates whether they form a positive pair, and \(m\) is the separation margin.

This is a deliberately simple contrastive baseline.

### C4 — Uncertainty

ORE preserves uncertainty instead of always returning a definite character.

Its output includes candidate graphemes, probability estimates, an explicit `<UNK>` candidate, entropy and visual-distance information.

The unknown/OOD estimate is currently heuristic, not a calibrated human-perception probability.

## 2. The implemented mathematical mechanisms

**A — Absolute position**

\[
A_{k,c}=\sum_i q_i(c)
\exp\left(-\frac{(p_i-\mu_k)^2}{2\sigma_{ik}^2}\right)
\]

**B — Relative/open-bigram coding**

\[
B_{a,b,g}=\sum_{i<j}q_i(a)q_j(b)\kappa_g(r_{ij})
\]

The system learns spacing profiles from training-only order targets and preserves the direction of each pair.

**O — Distributed overlap**

\[
O_{k,c}=\sum_i q_i(c)\mathcal{N}(k;\mu_i,\sigma_i^2)
\]

The discrete position distributions are normalized so that each patch's candidate activation mass is conserved.

**D6 — Trainable order model**

A pairwise logistic model learns whether one patch precedes another using Stage C visual features and signed positional descriptors. Reversed pairs provide explicit negative examples.

A and O currently use preregistered baseline widths; B spacing profiles and the pairwise relation model are learned. Adaptive learning of all kernel parameters remains future research.

## 3. An important correction to the learning algorithm

During implementation, I identified a potential target-leakage problem in the order-learning model.

The model initially received the known ordinal rank as an input. That would allow it to predict the training answer without actually learning the visual relationship.

I removed that input.

The final model receives:

\[
X_{ij}=[
z_i,\ z_j,\ z_j-z_i,\ |z_j-z_i|,\ d_{ij}
]
\]

Where \(z_i,z_j\) are Stage C visual representations and \(d_{ij}\) is unsigned physical spacing.

The known order is used only as the training target. Reversed pairs are generated as negative examples.

This is an important safeguard for future ORE experiments.

## Stage E — Orthographic Regularities and Chunk Learning

Stage E will build on the four completed stages by giving ORE a mechanism for discovering recurring written structures.

The central objective is to move beyond recognizing individual characters and learn that particular character combinations occur together, recur in different words, and carry useful statistical information.

For example, exposure to:

- `reading`
- `reader`
- `ready`
- `reached`

can help ORE discover recurring sequences and their distribution across different contexts.

However, **frequency alone will not qualify a sequence as a learned orthographic chunk**. ORE must demonstrate that the chunk has predictive value on previously unseen strings.

# ORE Stage E — Orthographic Regularities and Chunk Learning

<row align="center" gap={2}>
  <badge color="success">Implemented</badge>
  <badge color="success">74/74 tests passed</badge>
  <badge color="warning">Scientific validation pending</badge>

Stage E (E1–E5) is implemented. It builds on Stages A, B, C and D without replacing their functionality.

The result is ORE's first subsystem for learning recurring orthographic structures from exposure.

## 1. What has been implemented?

| Step | Algorithm | Implemented functionality |
|---|---|---|
| E1 | Learn orthographic statistics | Character frequencies, conditional transitions, local pairs and spacing between characters |
| E2 | Discover orthographic chunks | Automatically generate recurring sequences of 2 to K characters |
| E3 | Evaluate chunks | Compare independent-character encoding against chunk-based encoding using MDL-style calculations |
| E4 | Promote learned chunks | Promote candidates only when statistical and held-out validation conditions are satisfied |
| E5 | Maintain orthographic memory | Preserve lifetime knowledge, recent exposure, promotion history and persistent checkpoints |

### E1 — Statistical learning

ORE learns conditional probabilities:

\[
P(g_t\mid g_{t-1},g_{t-2},\ldots)
\]

It maintains both adjacent transitions and non-adjacent character relationships.

For example, it can learn that:

- `r` frequently precedes `e`.
- `e` frequently precedes `a` after `r`.
- `a` frequently precedes `d`.
- Certain character pairs recur despite intervening characters.

An important feature is that probabilities are preserved when character identities are uncertain.

For a sequence of probability distributions, expected transition counts are calculated using:

\[
N(h,g)\mathrel{+}=
\prod_{j\in h}q_j(h_j)\,q_t(g)
\]

This means the system does not have to convert every uncertain visual observation into one supposedly certain letter.

### E2 — Automatic chunk discovery

The system generates candidate sequences from training exposures.

For example:

<box border radius="lg" padding={3} gap={3}>
  **Example training exposures**

  <title size="xl" color="default">reading · reader · ready · reached</title>
  <divider color="subtle"/>
  **Potential recurring structures**

  <row wrap="wrap" gap={2}>
    {#each ["re","ea","rea","ad","ed"] as chunk}
      <box background="rgba(16,185,129,0.10)" radius="md" padding={{x:3,y:2}}>
        <title size="lg">{chunk}</title>
      </box>
    {/each}
  </row>
  <text color="secondary" size="xs">Illustrative candidates, not claims about what the model learned from a real reading corpus.</text>
</box>

Each candidate receives:
- Expected support.
- Number of distinct trusted strings.
- Left and right context diversity.
- Position distribution.
- Exposure provenance.
- Candidate probability and evaluation results.

Whole words are excluded as chunks by default. They require explicit configuration to be considered.

### E3 — Mathematical evaluation

ORE compares two models:

- \(M_0\): independent-character representation.
- \(M_u\): representation that includes candidate chunk \(u\).

The candidate score is:

\[
\Delta(u)=L(D\mid M_0)-L(D\mid M_u)-\lambda C(u)
\]

The implementation evaluates this separately on training and validation data.

**Important scientific qualification:** This is an MDL-style approximation, not a globally optimal minimum-description-length algorithm. Candidates are evaluated independently, so overlapping chunks can produce non-additive gains. This limitation is documented and should be addressed in a future joint segmentation model.

### E4 — Promotion conditions

A candidate is promoted only when it satisfies the configured conditions:

1. Sufficient training support.
2. Enough distinct training strings.
3. Adequate left-context diversity.
4. Adequate right-context diversity.
5. Positive held-out validation benefit after complexity cost.
6. Appropriate string-generalization evaluation protocol.

The test set never determines promotion.

### E5 — Persistent orthographic memory

Stage E integrates with Stage A's existing `PatternMemory`.

It maintains two separate types of memory:

\[
M=M_{\text{lifetime}}+M_{\text{recent}}
\]

Recent memory decays with exposure, while lifetime memory is preserved.

It also supports idempotent processing: running the same training exposures again does not count them twice.

[ASSISTANT]
# ORE Stage E — Orthographic Regularities and Chunk Learning

<row align="center" gap={2}>
  <badge color="success">Implemented</badge>
  <badge color="success">74/74 tests passed</badge>
  <badge color="warning">Scientific validation pending</badge>
</row>

Stage E (E1–E5) is implemented. It builds on Stages A, B, C and D without replacing their functionality.

The result is ORE's first subsystem for learning recurring orthographic structures from exposure.

## 1. What has been implemented?

| Step | Algorithm | Implemented functionality |
|---|---|---|
| E1 | Learn orthographic statistics | Character frequencies, conditional transitions, local pairs and spacing between characters |
| E2 | Discover orthographic chunks | Automatically generate recurring sequences of 2 to K characters |
| E3 | Evaluate chunks | Compare independent-character encoding against chunk-based encoding using MDL-style calculations |
| E4 | Promote learned chunks | Promote candidates only when statistical and held-out validation conditions are satisfied |
| E5 | Maintain orthographic memory | Preserve lifetime knowledge, recent exposure, promotion history and persistent checkpoints |

### E1 — Statistical learning

ORE learns conditional probabilities:

\[
P(g_t\mid g_{t-1},g_{t-2},\ldots)
\]

It maintains both adjacent transitions and non-adjacent character relationships.

For example, it can learn that:

- `r` frequently precedes `e`.
- `e` frequently precedes `a` after `r`.
- `a` frequently precedes `d`.
- Certain character pairs recur despite intervening characters.

An important feature is that probabilities are preserved when character identities are uncertain.

For a sequence of probability distributions, expected transition counts are calculated using:

\[
N(h,g)\mathrel{+}=
\prod_{j\in h}q_j(h_j)\,q_t(g)
\]

This means the system does not have to convert every uncertain visual observation into one supposedly certain letter.

### E2 — Automatic chunk discovery

The system generates candidate sequences from training exposures.

For example:

<box border radius="lg" padding={3} gap={3}>
  **Example training exposures**

  <title size="xl" color="default">reading · reader · ready · reached</title>
  <divider color="subtle"/>
  **Potential recurring structures**

  <row wrap="wrap" gap={2}>
    {#each ["re","ea","rea","ad","ed"] as chunk}
      <box background="rgba(16,185,129,0.10)" radius="md" padding={{x:3,y:2}}>
        <title size="lg">{chunk}</title>
      </box>
    {/each}
  </row>
  <text color="secondary" size="xs">Illustrative candidates, not claims about what the model learned from a real reading corpus.</text>
</box>

Each candidate receives:
- Expected support.
- Number of distinct trusted strings.
- Left and right context diversity.
- Position distribution.
- Exposure provenance.
- Candidate probability and evaluation results.

Whole words are excluded as chunks by default. They require explicit configuration to be considered.

### E3 — Mathematical evaluation

ORE compares two models:

- \(M_0\): independent-character representation.
- \(M_u\): representation that includes candidate chunk \(u\).

The candidate score is:

\[
\Delta(u)=L(D\mid M_0)-L(D\mid M_u)-\lambda C(u)
\]

The implementation evaluates this separately on training and validation data.

**Important scientific qualification:** This is an MDL-style approximation, not a globally optimal minimum-description-length algorithm. Candidates are evaluated independently, so overlapping chunks can produce non-additive gains. This limitation is documented and should be addressed in a future joint segmentation model.

### E4 — Promotion conditions

A candidate is promoted only when it satisfies the configured conditions:

1. Sufficient training support.
2. Enough distinct training strings.
3. Adequate left-context diversity.
4. Adequate right-context diversity.
5. Positive held-out validation benefit after complexity cost.
6. Appropriate string-generalization evaluation protocol.

The test set never determines promotion.

### E5 — Persistent orthographic memory

Stage E integrates with Stage A's existing `PatternMemory`.

It maintains two separate types of memory:

\[
M=M_{\text{lifetime}}+M_{\text{recent}}
\]

Recent memory decays with exposure, while lifetime memory is preserved.

It also supports idempotent processing: running the same training exposures again does not count them twice.
