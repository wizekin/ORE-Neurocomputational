## 3. Important mathematical mechanisms

The implementation includes:

**Hierarchical prediction**

\[
\mu_j(h)=g_j(intent,domain)
\]

**Prediction error**

\[
\epsilon_j=y_j-\mu_j(h)
\]

**Precision weighting**

\[
\Pi_j=\frac{c}{\sigma_j^2}
\]

**Variational free energy**

\[
F(q)=\sum_h q(h)E(h)+\beta KL(q\|p)
\]

**Belief revision**

\[
q_{t+1}=
softmax(\log(q_t)-\eta\nabla_qF)
\]

The belief update includes backtracking to prevent accepted updates from increasing the objective.

## 5. Important scientific distinction

N7 is a computational approximation of predictive processing, not yet a biological simulation of the actual neural circuits.

In particular:
- Generative-model parameters are currently configured rather than biologically learned.
- Observation precision uses configured variances.
- Syntax and semantic providers are accepted as contextual inputs, but this implementation does not perform complete syntax parsing or semantic understanding.
- Independent empirical validation remains necessary.

The implementation should therefore be considered a software-complete experimental N7 prototype, not scientifically validated brain replication.

# ORE Neurocomputational Development Roadmap — Phase N8: Brain-Data Validation

**N8 objective:** Determine whether the mechanisms implemented in ORE actually explain measurable aspects of human visual and orthographic processing, rather than merely producing plausible computational results.

N8 is fundamentally different from N0–N7. Those phases construct computational mechanisms inspired by brain functions. N8 tests whether those mechanisms correspond to real human behavior and, where suitable data are available, measurable neural activity.

One important clarification: I recovered the N8 objective and its dependencies from our previous work, but not the complete original numbered N8 sequence. Therefore, the following is a proposed, comprehensive 72-operation algorithm that develops the recovered N8 objective into an implementable scientific validation architecture. It is not a claim that these exact 72 operations were already in the original roadmap.

## 1. Scientific foundations and dependencies

N8 evaluates the complete processing chain:

    </list-item>

N8 must preserve an important distinction: visual evidence, orthographic evidence, lexical hypotheses, and contextual predictions must remain separately accessible. Otherwise, a contextual correction could conceal a visual-recognition failure.

### What N8 must establish

1. Does ORE reproduce human reading and visual-recognition behavior?
2. Do its intermediate representations correspond to measurable neural responses?
3. Does predictive feedback improve recognition in the same circumstances in which it improves human recognition?
4. Does the model reproduce human responses to ambiguity, noise, unfamiliar fonts, and unfamiliar writers?
5. Are the mechanisms necessary, or can simpler alternative models explain the same results?
6. Does the architecture generalize to previously unseen visual data?

# 2. The complete N8 algorithm — 72 operations

The algorithm contains 12 subsystems, each containing six operations.

## Subsystem A — Scientific hypothesis construction

<badge color="info">Operations 1–6</badge>

**Purpose:** Convert every important ORE mechanism into a falsifiable scientific hypothesis.

### Operation 1 — Extract the mechanisms to validate

Collect the implemented mechanisms from N1–N7.

For each mechanism, record:

- Its biological inspiration.
- Its implementation in ORE.
- Its input and output.
- Its mathematical model.
- Its expected effect on recognition.
- Its expected observable neural or behavioral effect.

For example, N3 recurrent prediction should have an explicitly testable hypothesis: feedback from higher-level representations should improve the interpretation of incomplete or ambiguous lower-level visual evidence.

**Mathematical operation:**

Represent each mechanism as a parameterized function:

\[
y_i=f_i(x_i,\theta_i)
\]

Where:

- \(x_i\) is the mechanism's input.
- \(\theta_i\) is its parameter set.
- \(y_i\) is its output.

### Operation 2 — Define the biological hypothesis

Translate the computational mechanism into a claim about human processing.

Example:

"When visual evidence is degraded, contextual information should have a greater influence on the recognition decision."

Define the expected relationship:

\[
P(R\mid V_d,C)>P(R\mid V_d)
\]

Here, \(V_d\) is degraded visual evidence, \(C\) is context, and \(R\) is correct recognition.

The hypothesis must also specify circumstances where the effect should not occur or should be reduced.

### Operation 3 — Define measurable predictions

Each hypothesis must have measurable outcomes.

Examples:

- Recognition accuracy.
- Reaction time.
- Error type.
- Confidence.
- Eye movement, if recorded.
- EEG/MEG response amplitude and timing.
- fMRI activation or representational similarity.

A prediction should be expressed as a measurable difference:

\[
\Delta M=M_{\text{experimental}}-M_{\text{control}}
\]

### Operation 4 — Define the competing explanations

Construct alternative models.

For example:

- Feedforward-only visual recognition.
- Feedforward recognition with lateral interactions.
- Recurrent recognition without contextual feedback.
- Full ORE with contextual feedback.
- A conventional OCR baseline.

The purpose is to test whether the proposed brain-inspired mechanisms explain something that simpler alternatives cannot.

### Operation 5 — Define the biological timescales

Assign expected timescales to the mechanisms.

For example:

- Early visual responses.
- Intermediate visual and orthographic processing.
- Later recurrent and contextual influences.
- Longer-term memory-related effects.

Do not assign a biological timescale merely because an ORE operation executes at a particular point in Python. Neural timing must be measured independently.

### Operation 6 — Construct the hypothesis registry

Store every hypothesis in a machine-readable record.

Example:

The output is a registry connecting ORE mechanisms to measurable scientific predictions.

## Subsystem B — Brain-data acquisition and dataset construction

<badge color="info">Operations 7–12</badge>

**Purpose:** Obtain independent data representing real human visual and reading behavior.

<AsyncImageGroup query={["human EEG visual word recognition experiment laboratory","MEG brain imaging reading experiment","fMRI visual word processing experiment"]} aspectRatio="5:4" layout="carousel"/>

### Operation 7 — Acquire visual recognition datasets

Collect rights-cleared visual samples containing:

- Printed letters.
- Words.
- Pseudowords.
- Different typefaces.
- Different sizes.
- Different contrast levels.
- Degraded and noisy images.
- Latin and Arabic writing.

The dataset should contain original image files and verified labels.

### Operation 8 — Acquire human behavioral data

Collect human responses to the same or closely matched stimuli.

For every trial, record:

\[
D_t=(I_t,C_t,R_t,T_t,S_t)
\]

Where:

- \(I_t\): presented image.
- \(C_t\): contextual condition.
- \(R_t\): participant response.
- \(T_t\): response time.
- \(S_t\): stimulus metadata.

If possible, collect confidence ratings as well.

### Operation 9 — Acquire neural measurements

Where ethically and practically available, obtain:

- EEG.
- MEG.
- fMRI.
- Eye-tracking measurements.

Each measurement has different temporal and spatial resolution.

For example, EEG and MEG can investigate temporal processing, while fMRI can investigate spatial patterns of activity.

### Operation 10 — Construct a unified experimental record

Associate the stimulus, participant response, experimental condition, and neural recording.

An experimental record can be represented as:

\[
E_t=(I_t,L_t,C_t,B_t,N_t)
\]

Where \(L_t\) is the verified label, \(B_t\) is behavioral data, and \(N_t\) is neural data.

Missing measurements must remain explicitly marked as missing rather than replaced with invented values.

### Operation 11 — Verify labels and experimental provenance

Check:

- Whether labels are correct.
- Whether stimuli have duplicate identities.
- Whether image transformations are documented.
- Whether participant identifiers are pseudonymized.
- Whether data permissions allow the intended research.
- Whether the original experimental protocol is available.

For labeled observations, calculate an error rate:

\[
E_{\text{label}}=
\frac{N_{\text{incorrect labels}}}
{N_{\text{verified labels}}}
\]

The expected value for an accepted ground-truth dataset is zero incorrect labels in the verified subset.

### Operation 12 — Build independent dataset partitions

Split data into:

- Training data.
- Validation data.
- Testing data.
- External evaluation data.

Use participant-independent and writer-independent splits where applicable.

Also separate fonts and stimulus sources to prevent information leakage.

For example:

\[
D=D_{\text{train}}\cup D_{\text{validation}}
\cup D_{\text{test}}\cup D_{\text{external}}
\]

The sets must be disjoint according to the intended generalization unit.

**Important:** If images from the same writer appear in both training and testing, the system may learn writer-specific characteristics rather than general visual recognition.

## Subsystem C — Biological signal preprocessing

<badge color="info">Operations 13–18</badge>

**Purpose:** Convert recorded neural measurements into scientifically usable signals without removing the effects being investigated.

<AsyncImageGroup query={["EEG signal raw and filtered waveform example","EEG event related potential waveform visual stimulus","fMRI brain activation statistical map"]} aspectRatio="5:4"/>

### Operation 13 — Inspect raw neural signals

Load the original recordings and examine:

- Sampling frequency.
- Channel count.
- Recording duration.
- Missing samples.
- Sensor failures.
- Recording artifacts.
- Event markers.

For a sampled signal:

\[
x[n]=x(n\Delta t)
\]

Where:

\[
\Delta t=\frac{1}{f_s}
\]

and \(f_s\) is the sampling frequency.

### Operation 14 — Remove or identify artifacts

Identify eye movements, muscle activity, electrical interference, and other artifacts.

A simplified observed EEG model is:

\[
x(t)=s(t)+a(t)+\eta(t)
\]

Where:

- \(s(t)\) is the neural signal of interest.
- \(a(t)\) is artifact activity.
- \(\eta(t)\) is background noise.

Artifact rejection and correction must be documented. Avoid processing choices that selectively remove the neural effect being tested.

### Operation 15 — Filter neural signals

Apply appropriate frequency filtering according to the experimental question.

A digital filtering operation can be represented as:

\[
y[n]=\sum_{k=0}^{K}b_kx[n-k]
-\sum_{k=1}^{P}a_ky[n-k]
\]

The filter parameters must be recorded and tested for distortion.

### Operation 16 — Align signals with stimulus presentation

Use event markers to align neural recordings to the actual onset of each stimulus.

For each trial:

\[
X_i(\tau)=x(t_i+\tau)
\]

Where \(t_i\) is the event onset and \(\tau\) is time relative to that event.

This permits examination of the neural response following stimulus presentation.

### Operation 17 — Construct trial-level neural representations

Create a separate signal representation for each experimental trial.

For EEG, this might be:

\[
X\in\mathbb{R}^{N\times C\times T}
\]

Where:

- \(N\) is the number of trials.
- \(C\) is the number of channels.
- \(T\) is the number of time samples.

Keep individual trials available instead of relying exclusively on averaged signals.

### Operation 18 — Quantify signal quality and reliability

Calculate signal-to-noise ratio, trial retention, and measurement reliability.

A simplified signal-to-noise ratio is:

\[
SNR=10\log_{10}
\left(\frac{P_{\text{signal}}}{P_{\text{noise}}}\right)
\]

For repeated measurements, estimate reliability using appropriate measures such as split-half reliability or intraclass correlation.

Reject or flag recordings that fail predefined quality criteria.

## Subsystem D — Human behavioral validation

<badge color="info">Operations 19–24</badge>

**Purpose:** Test whether ORE behaves like a human visual recognition system.

### Operation 19 — Construct controlled visual stimuli

Create stimulus groups that vary one or more controlled factors:

- Image quality.
- Contrast.
- Font.
- Character spacing.
- Word familiarity.
- Context strength.
- Visual ambiguity.

Use matched conditions so that the effect of each variable can be isolated.

### Operation 20 — Measure human recognition accuracy

Calculate:

\[
Accuracy=\frac{N_{\text{correct}}}{N_{\text{trials}}}
\]

Calculate character error rate and word error rate where appropriate:

\[
CER=\frac{S_c+D_c+I_c}{N_c}
\]

\[
WER=\frac{S_w+D_w+I_w}{N_w}
\]

Where \(S,D,I\) are substitutions, deletions, and insertions.

### Operation 21 — Measure human reaction time

For each participant, calculate the reaction-time distribution.

\[
RT_{\text{mean}}=\frac{1}{N}\sum_{i=1}^{N}RT_i
\]

Examine the distribution rather than relying exclusively on the mean, since reaction times are often skewed.

### Operation 22 — Measure human sensitivity to visual degradation

Compare recognition performance across image-quality levels.

For example:

\[
\Delta A=A_{\text{clear}}-A_{\text{degraded}}
\]

A model should reproduce not only the overall accuracy but also how recognition deteriorates as visual information is removed.

### Operation 23 — Measure contextual influence

Compare context conditions while holding visual evidence constant.

For example:

- Strongly predictive context.
- Weakly predictive context.
- Neutral context.
- Misleading context.

Calculate:

\[
\Delta C=A_{\text{predictive}}-A_{\text{neutral}}
\]

Also measure whether misleading context increases incorrect recognition.

### Operation 24 — Construct human behavioral reference curves

Build reference curves for:

- Accuracy versus image degradation.
- Reaction time versus visual ambiguity.
- Context strength versus recognition.
- Word familiarity versus recognition.
- Confidence versus accuracy.

These curves become the behavioral reference against which ORE is evaluated.

## Subsystem E — ORE experimental execution

<badge color="info">Operations 25–30</badge>

**Purpose:** Run the complete ORE pipeline under the same experimental conditions as the human experiments.

### Operation 25 — Freeze the experimental ORE configuration

Record:

- Git commit.
- N0–N7 versions.
- Python environment.
- Model configuration.
- Random seeds.
- Dataset hashes.
- Processing parameters.

This ensures that results can be reproduced.

### Operation 26 — Present identical visual inputs to ORE

Use the same image stimuli that were presented to human participants.

Do not allow ORE to access ground-truth labels or test answers during recognition.

### Operation 27 — Capture N1 early visual outputs

Record:

- Orientation responses.
- Contrast-normalized maps.
- Spatial features.
- Feature activations.
- Uncertainty measurements.

For example, a Gabor-like filter can be represented as:

\[
G(x,y)=
\exp\left(
-\frac{x'^2+\gamma^2y'^2}{2\sigma^2}
\right)
\cos\left(\frac{2\pi x'}{\lambda}+\phi\right)
\]

where \(x'\) and \(y'\) are rotated coordinates.

The output is a collection of feature-response maps.

### Operation 28 — Capture N2–N3 representations

Record grapheme activations, structural relationships, and recurrent visual states.

For a population of units:

\[
\mathbf{a}(t)=
\begin{bmatrix}
a_1(t)\\
a_2(t)\\
\vdots\\
a_n(t)
\end{bmatrix}
\]

Track how the population changes during recognition.

### Operation 29 — Capture N4–N5 processing states

Record:

- Attention weights.
- Precision values.
- Inhibitory activity.
- Excitatory activity.
- Recurrent feedback.
- Convergence measurements.

For example, a normalized attention distribution can be represented as:

\[
\alpha_i=
\frac{\exp(z_i)}
{\sum_j\exp(z_j)}
\]

The goal is to determine whether attention and recurrent processing produce the predicted effects.

### Operation 30 — Capture N6–N7 outputs

Record separately:

- Visual evidence.
- Orthographic evidence.
- Sequence hypotheses.
- Lexical candidates.
- Contextual predictions.
- Prediction errors.
- Final recognition.
- Confidence and uncertainty.

Preserve the original evidence and priors separately. This is essential for identifying whether a correct final answer was reached from visual evidence or through contextual correction.

## Subsystem F — Computational and behavioral comparison

<badge color="info">Operations 31–36</badge>

**Purpose:** Determine how closely ORE's recognition behavior matches human behavior.

### Operation 31 — Align ORE and human observations

Match the same stimuli and experimental conditions.

For example:

\[
H_i=(A_i,RT_i)
\]

\[
O_i=(A_i^{ORE},RT_i^{ORE})
\]

The comparison must account for the fact that ORE processing time is not automatically equivalent to human reaction time.

### Operation 32 — Compare recognition accuracy

Calculate the difference between ORE and human accuracy:

\[
E_A=
\left|A_{ORE}-A_{Human}\right|
\]

Calculate this separately for each condition, font, degradation level, and language.

### Operation 33 — Compare error patterns

Do not compare only the number of mistakes.

Compare the types of mistakes.

For example, two systems may both achieve 90% accuracy but make completely different character substitutions.

Construct a confusion matrix:

\[
C_{ij}=
\#(\text{true class}=i,\text{predicted class}=j)
\]

Compare the normalized confusion matrices using a suitable distance measure.

### Operation 34 — Compare behavioral sensitivity

Compare the slopes of the human and ORE performance curves.

For example:

\[
\frac{\partial A_{Human}}{\partial Q}
\quad\text{versus}\quad
\frac{\partial A_{ORE}}{\partial Q}
\]

Where \(Q\) represents visual quality.

A good model should reproduce the direction and relevant shape of the human performance change, not just one accuracy value.

### Operation 35 — Compare context-related behavior

Test whether ORE and humans show comparable contextual benefits and contextual errors.

Measure:

- Benefit from predictive context.
- Resistance to misleading context.
- Recognition of unexpected words.
- Reliance on context under visual degradation.

### Operation 36 — Compare confidence calibration

Compare confidence against actual correctness.

For ORE, use calibration error:

\[
ECE=
\sum_{b=1}^{B}
\frac{|S_b|}{N}
\left|
acc(S_b)-conf(S_b)
\right|
\]

Human confidence ratings can be analyzed separately.

The aim is to determine whether ORE's uncertainty corresponds to the difficulty experienced by human readers.

## Subsystem G — Neural representational validation

<badge color="info">Operations 37–42</badge>

**Purpose:** Test whether internal ORE representations resemble measurable patterns of human neural activity.

<AsyncImageGroup query={["EEG event related potential topographic scalp maps","fMRI representational similarity matrix brain decoding","visual cortex fMRI activation map"]} aspectRatio="5:4"/>

### Operation 37 — Define candidate brain-processing correspondences

Define hypotheses connecting ORE subsystems to neural systems.

For example:

| ORE mechanism | Candidate biological correspondence |
|---|---|
| N1 visual filtering | Early visual cortical processing |
| N2 grapheme representation | Visual and orthographic processing networks |
| N3 recurrent representation | Recurrent interactions in visual processing |
| N4 attention | Attentional modulation |
| N5 recurrent dynamics | Interacting neural populations |
| N6 memory | Memory-related processing networks |
| N7 contextual prediction | Higher-level feedback and contextual integration |

These are hypotheses, not established one-to-one mappings.

### Operation 38 — Extract ORE representational vectors

For every stimulus, extract activation vectors from the relevant ORE subsystem.

\[
\mathbf{r}_i^{ORE}\in\mathbb{R}^{d}
\]

Where \(d\) is the number of features or units.

### Operation 39 — Extract neural representational vectors

Extract comparable neural patterns from EEG, MEG, or fMRI.

\[
\mathbf{r}_i^{brain}\in\mathbb{R}^{m}
\]

The number of dimensions \(m\) need not equal \(d\).

### Operation 40 — Construct representational dissimilarity matrices

Calculate pairwise distances between stimuli.

For example:

\[
D_{ij}^{ORE}
=
1-\operatorname{corr}
(\mathbf{r}_i^{ORE},\mathbf{r}_j^{ORE})
\]

And:

\[
D_{ij}^{brain}
=
1-\operatorname{corr}
(\mathbf{r}_i^{brain},\mathbf{r}_j^{brain})
\]

These matrices describe how stimuli are represented relative to each other.

### Operation 41 — Compare representational geometry

Compare the two matrices using correlation or other appropriate similarity measures.

\[
RSA=
\operatorname{corr}
\left(
\operatorname{vec}(D^{ORE}),
\operatorname{vec}(D^{brain})
\right)
\]

Use appropriate cross-validation and permutation tests.

A high similarity supports the representational hypothesis but does not establish that the brain uses the same implementation.

### Operation 42 — Test hierarchical representation correspondence

Compare ORE stages against neural data at different levels.

For example:

- N1 against early visual responses.
- N2–N3 against visual and orthographic representations.
- N6–N7 against higher-level contextual representations.

Test whether the correspondence changes across processing stages as predicted.

## Subsystem H — Temporal and predictive-processing validation

<badge color="info">Operations 43–48</badge>

**Purpose:** Test whether ORE's predictions, feedback, and error signals correspond to the timing and behavior of human neural responses.

### Operation 43 — Establish neural response time windows

Identify response windows from the experimental data and independently justified literature.

Do not automatically assign an ORE subsystem to a named EEG component simply because its function sounds similar.

### Operation 44 — Measure neural response to visual ambiguity

Compare responses to:

- Clear stimuli.
- Ambiguous stimuli.
- Degraded stimuli.
- Unexpected stimuli.

Estimate how neural responses change with visual uncertainty.

### Operation 45 — Test contextual prediction effects

Compare predictable and unpredictable stimuli while controlling visual properties.

Measure whether contextual expectation affects neural activity, behavioral responses, or both.

### Operation 46 — Test prediction-error sensitivity

In N7, a simplified prediction error is:

\[
\epsilon_j=y_j-\mu_j
\]

And its precision-weighted form is:

\[
\epsilon_j^{*}=\Pi_j\epsilon_j
\]

Test whether ORE's error magnitude changes in the same experimental conditions in which human neural responses show prediction-related sensitivity.

### Operation 47 — Test precision and uncertainty effects

In ORE, precision may be approximated as:

\[
\Pi_j=\frac{1}{\sigma_j^2}
\]

Test whether the model's precision modulation predicts when visual evidence or contextual evidence has greater influence.

This is particularly important for degraded images and misleading contexts.

### Operation 48 — Test recurrent feedback predictions

Compare full recurrent ORE against feedforward-only versions.

If recurrent feedback is essential, removing it should produce a measurable loss in the specific conditions predicted by the hypothesis.

The experiment must also identify whether the effect occurs at the expected neural timescale.

## Subsystem I — Ablation and causal-mechanism validation

<badge color="info">Operations 49–54</badge>

**Purpose:** Discover which ORE mechanisms are actually responsible for observed improvements.

### Operation 49 — Construct the complete reference model

Run full N0–N7 ORE.

Save all outputs, predictions, errors, and intermediate states.

This becomes the reference configuration.

### Operation 50 — Disable N3 recurrent prediction

Remove or disable recurrent feedback while keeping other components as comparable as possible.

Measure:

\[
\Delta M_{N3}
=
M_{\text{full}}-M_{\text{without N3 feedback}}
\]

### Operation 51 — Disable N4 precision modulation

Run the same experiment without attention/precision modulation.

Measure the change in recognition, uncertainty, and contextual dependence.

### Operation 52 — Disable N5 recurrent neural dynamics

Remove the selected N5 recurrent mechanisms.

Test whether recognition and neural correspondence deteriorate in the predicted circumstances.

### Operation 53 — Disable N6 memory and N7 contextual prediction

Test memory and contextual feedback separately.

This distinction matters: memory-based recognition and immediate contextual prediction should not be treated as identical mechanisms.

### Operation 54 — Perform factorial ablation analysis

Test combinations of mechanisms rather than removing only one at a time.

For two mechanisms \(A\) and \(B\), estimate their interaction:

\[
I_{AB}
=
M_{AB}-M_A-M_B+M_0
\]

Where:

- \(M_{AB}\) is performance with both mechanisms.
- \(M_A\) and \(M_B\) are the individual conditions.
- \(M_0\) is the baseline.

This tests whether mechanisms interact rather than simply contribute independently.

## Subsystem J — Statistical validation and uncertainty

<badge color="info">Operations 55–60</badge>

**Purpose:** Determine whether observed similarities and differences are statistically reliable.

### Operation 55 — Estimate confidence intervals

Use bootstrap resampling to estimate uncertainty around behavioral and neural measurements.

For an observed metric \(M\), generate:

\[
M^{(1)},M^{(2)},\ldots,M^{(B)}
\]

Then calculate confidence intervals from the bootstrap distribution.

Resample at the appropriate independent unit, such as participant, rather than treating all trials as independent participants.

### Operation 56 — Perform permutation tests

Test whether a measured relationship exceeds what would be expected under a suitable null hypothesis.

For example, randomly permute stimulus labels while preserving the relevant experimental structure.

Calculate:

\[
p=
\frac{1+\#(|T_{perm}|\geq |T_{observed}|)}
{1+B}
\]

### Operation 57 — Apply mixed-effects models

Human observations often vary by participant and stimulus.

A mixed-effects model can represent this:

\[
Y_{ij}=
\beta_0+\beta_1X_{ij}
+u_i+v_j+\epsilon_{ij}
\]

Where:

- \(u_i\) represents participant-level variation.
- \(v_j\) represents stimulus-level variation.
- \(\epsilon_{ij}\) is residual variation.

This prevents conclusions from depending on a small number of unusually easy participants or stimuli.

### Operation 58 — Compare candidate models

Compare ORE against alternative models using appropriate held-out predictive performance, likelihood-based criteria, or Bayesian model comparison.

For example:

\[
\Delta E=E_{\text{baseline}}-E_{\text{ORE}}
\]

A positive value indicates that ORE has lower error than the baseline under the chosen metric.

### Operation 59 — Correct for multiple comparisons

N8 may test many:

- Brain regions.
- Channels.
- Time windows.
- Stimulus categories.
- Mechanisms.
- Experimental conditions.

Use an appropriate correction method, such as false discovery rate control or family-wise error control.

### Operation 60 — Quantify model uncertainty and reliability

Repeat ORE experiments across multiple random seeds and relevant dataset partitions.

Calculate:

\[
\bar M=\frac{1}{K}\sum_{k=1}^{K}M_k
\]

\[
SD(M)=
\sqrt{
\frac{1}{K-1}
\sum_{k=1}^{K}(M_k-\bar M)^2
}
\]

A result that appears only under one seed or one partition is not sufficiently reliable.

# 3. Mathematical mechanisms: what happens in the brain versus what N8 calculates

A critical distinction is necessary before implementing this algorithm.

N8 contains two different kinds of mathematics:

1. **Candidate neural computations:** mathematical approximations of processes that might occur in biological neural networks.
2. **Scientific validation mathematics:** statistical operations performed by researchers to compare ORE with human data.

These must not be confused.

| Mathematical mechanism | Candidate biological interpretation | N8 role |
|---|---|---|
| Convolution | Receptive-field filtering | Model N1 visual responses |
| Normalization | Gain control and response normalization | Compare visual processing |
| Population coding | Distributed neural representations | Compare N2–N5 representations |
| Recurrent dynamics | Feedback and interacting populations | Test N3/N5 mechanisms |
| Bayesian inference | Probabilistic interpretation of uncertain evidence | Evaluate N7 predictions |
| Precision weighting | Reliability-dependent influence of signals | Test N4/N7 hypotheses |
| Synaptic plasticity | Experience-dependent changes | Evaluate learning mechanisms |
| Temporal integration | Accumulation of information over time | Compare neural timing |
| Correlation and RSA | Not assumed to be a literal neural computation | Compare representational structure |
| Bootstrap and permutation tests | Researcher-side statistical tools | Evaluate evidence reliability |

The brain does not literally execute Python operations, calculate p-values, or run bootstrap resampling. Those are scientific methods used to determine whether our computational hypotheses explain brain behavior.

---

# 4. Core mathematical framework for N8

The 72 operations can be organized around five central mathematical models.

## A. Behavioral similarity

\[
E_{behavior}=
w_1E_{accuracy}
+w_2E_{RT}
+w_3E_{confusion}
+w_4E_{calibration}
\]

This measures the difference between ORE and human behavior.

The weights must be predefined or justified, rather than adjusted after seeing the results.

## B. Neural representational similarity

\[
E_{representation}
=
1-\operatorname{corr}
\left(
\operatorname{vec}(D^{ORE}),
\operatorname{vec}(D^{brain})
\right)
\]

This compares the relationships between stimuli in ORE and the brain.

## C. Temporal prediction similarity

\[
E_{temporal}
=
\frac{1}{T}
\sum_{t=1}^{T}
\left(
R_{ORE}(t)-R_{brain}(t)
\right)^2
\]

Here, the responses must be measured on compatible timescales and with an appropriate signal representation.

## D. Mechanism contribution

\[
\Delta M_i=M_{\text{full}}-M_{\text{ablated},i}
\]

This estimates how much a mechanism contributes to a particular metric.

## E. Overall scientific evaluation

Rather than collapsing all evidence into a single number, N8 should maintain a vector of validation results:

\[
V_{N8}=
\begin{bmatrix}
V_{behavior}\\
V_{neural}\\
V_{temporal}\\
V_{causal}\\
V_{generalization}\\
V_{replication}
\end{bmatrix}
\]

This is important because a system can reproduce human behavioral performance without reproducing the mechanisms that generated that behavior.

# 6. Scientific acceptance criteria

N8 should not be marked scientifically complete simply because all 72 Python operations execute successfully.

| Validation dimension | Minimum acceptance requirement |
|---|---|
| Experimental integrity | No test-set leakage; provenance and labels verified |
| Behavioral validity | ORE reproduces predefined human behavioral effects within justified uncertainty |
| Error structure | Similarity in relevant error patterns, not accuracy alone |
| Neural representation | Reproducible representational correspondence on held-out data |
| Temporal validity | Predicted neural timing effects tested with appropriate measurements |
| Predictive processing | Context and prediction-error hypotheses tested against controls |
| Mechanistic validity | Ablations demonstrate predicted mechanism contributions |
| Generalization | Independent fonts, writers, and datasets |
| Replication | Central findings reproduced independently |
| Reproducibility | Frozen configurations and complete experimental records |

**Three levels of success must remain separate:**

- <badge color="success">Engineering success</badge> The N8 software runs and produces reproducible results.
- <badge color="info">Behavioral success</badge> ORE reproduces specified human recognition behavior.
- <badge color="discovery">Neurobiological support</badge> Independent neural evidence supports the proposed processing mechanisms.

A successful first level does not establish the second or third.

# 7. What N8 would mean for ORE

The major scientific question is not whether ORE can recognize letters and words. Conventional OCR already demonstrates that computers can do this.

The more important question is:

**Can ORE reproduce the underlying functional relationships between visual evidence, distributed representations, recurrent processing, attention, memory, prediction, uncertainty, and human recognition?**

For example, consider a partially obscured letter in a word.

<AsyncImage query="visual word recognition partially occluded letters perceptual ambiguity psychology experiment" aspectRatio="16:9" width="100%"/>

A scientifically useful ORE experiment would:

1. Present the same incomplete letter to human participants and ORE.
2. Change the surrounding word context while keeping the visual image unchanged.
3. Measure how recognition changes.
4. Measure whether misleading context produces false corrections.
5. Record ORE's visual evidence before contextual processing.
6. Compare human and ORE behavioral results.
7. Where possible, compare neural responses over time.
8. Disable contextual feedback and determine whether the predicted effects disappear.

This single experiment could test multiple N3, N4, N6, and N7 mechanisms together.

The critical achievement would be demonstrating that ORE reproduces not only the final recognition result, but also the experimentally observed relationships between evidence, uncertainty, context, and processing time.

**My recommendation:** Keep N8 independent of N0–N7, preserve their existing implementations, and make N8 a rigorous experimental validation framework. The next step after this algorithm is to turn the 72 operations into a detailed Python implementation plan with explicit input/output contracts, mathematical functions, tests, and scientific acceptance gates for every operation. <MemoryCite />
