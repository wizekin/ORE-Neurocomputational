## 3. SYS-08: PUD structural-frequency investigation

This is the most useful new development from this review.

The existing PUD generator extracts sentences and creates naturalistic cases, but it does not calculate structural-frequency diagnostics.

I therefore performed a read-only structural analysis against the exact pinned English and Arabic CoNLL-U files using their Git blob identities.

**English source:** [UD_English-PUD pinned commit](https://github.com/UniversalDependencies/UD_English-PUD/tree/a697bab43d4111073356de0df5802488bca3de7e)

**Arabic source:** [UD_Arabic-PUD pinned commit](https://github.com/UniversalDependencies/UD_Arabic-PUD/tree/c606299bc9eb8baa6c61c8dd3efc9a0fbf73aa87)

Each source contains 1,000 sentences.

The following are sentence-level syntactic proxies, not semantic interpretations.

|---|---:|---:|
| Relative clause (`acl:relcl`) | 193 | 265 |
| Active transitive root | 293 | 205 |
| Copular predicate | 186 | 54 |
| Clause complement (`ccomp`/`xcomp`) | 245 | 189 |
| Passive verb root | 140 | 72 |
| Adverbial clause | 156 | 167 |
| Coordination | 155 | 144 |

The active-transitive surface-order distribution was:

- English: SVO 292, VOS 1.
- Arabic: VSO 157, SVO 34, VOS 14.

<text color="secondary" size="xs">These figures are derived from dependency and POS annotations in the pinned PUD files. They do not represent USG semantic roles or independent semantic gold.</text>

### Selected construction candidate

<badge color="info">Candidate only</badge>

**Relative-clause attachment (`acl:relcl`) should be the next construction investigated.**

Reasons:

1. It occurs in both languages at meaningful frequencies: 19.3% of English sentences and 26.5% of Arabic sentences.
2. It is outside the accepted Phase 5 simple-transitive SVO/VSO baseline.
3. It directly aligns with Phase 6 continuation item P6-CONT-02, which identifies broader relative-clause and argument-gap attachment as an outstanding capability.
4. It gives us a concrete, bounded target for positive, negative, ambiguous and attachment-boundary fixtures.

This is a frequency-based candidate selection, not evidence that USG can already interpret relative clauses correctly.

**SYS-08 remains incomplete:** the measurements have not yet been implemented as a reproducible repository diagnostic, regression-tested and attached to the PUD campaign artifacts.

The next acceptance work should freeze those fixtures before any runtime syntax changes.

### Important automation blocker

I inspected the campaign publication workflow and repository settings.

Two conditions currently prevent reliable automatic publication:

1. GitHub Actions is not permitted to create or approve pull requests. This was directly confirmed by the OW-7 log:
   `GitHub Actions is not permitted to create or approve pull requests.`
2. Repository metadata reports `allow_auto_merge=false`.

The PUD workflow also has a publication step that does not use `continue-on-error`. Consequently, the first campaign could successfully upload its artifact and then fail during PR creation. Its subsequent auto-merge step would not run.

The safe resolution is to enable Actions PR creation and repository auto-merge, then verify required checks before relying on automatic publication.

Until the first full campaign is completed and its report/publication behavior is verified, the naturalistic population remains **not established**.

## 7. Documentation and governance drift

Three inconsistencies need attention.

**First — growth planner freshness.**

The newest growth-plan artifact is from [run 43373246201](https://github.com/wizekin/USG-Workbench/actions/runs/43373246201).

It analyzed only OWC-OW6 and identified 68 syntax first blockers. It also recorded a pipeline-version mismatch for 1,058 Phase 5 records.

It did not incorporate OWC-OW7, whose first-blocker profile is substantially different: lexical 61, syntax 16 and discourse 1.

The reason is that OWC-OW7 is not yet committed to main. Its artifact is available, but the growth planner's committed-campaign input does not include it.

**Second — system evidence catalogue freshness.**

[System evidence collection](https://github.com/wizekin/USG-Workbench/actions/runs/43378257188) produced an accepted snapshot, but it is now outdated.

It reports nine logical lexical batches, 150,602 headwords and the older OWC-6 campaign. The latest committed lexical branch and OWC-7 artifact are newer.

The collector also recorded only 100 workflow definitions out of the 129 identified in the inventory. Workflow inventory completeness needs improvement.

**Third — backlog sequencing.**

The current [improvement backlog](https://github.com/wizekin/USG-Workbench/blob/main/documentation/USG-SYSTEM-IMPROVEMENT-BACKLOG.md) still places SYS-16 before SYS-08/SYS-09.

That conflicts with the updated dependency order specified for the supervisor. The backlog should be reconciled rather than allowing an older plan to steer future development.

The capability assessment itself remains a historical snapshot, so its older lexical metrics should not be presented as current results.

- [`tools/system_evidence/collector.py`](https://github.com/wizekin/USG-Workbench/blob/main/tools/system_evidence/collector.py)
- [`tools/system_evidence/freshness.py`](https://github.com/wizekin/USG-Workbench/blob/main/tools/system_evidence/freshness.py)

- `physical_file_count = 32`
- `duplicate_physical_copy_count = 1`

**Conclusion:** the latest catalogue's shard-mismatch and stale-evaluation warnings are false positives. The lexical evaluation is current for the 31 logical batches, even though the catalogue currently rejects it.

The current tests encode the physical-count-equals-logical-count assumption, so this requires a regression correction rather than simply changing the report.
