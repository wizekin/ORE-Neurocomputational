## **3. How we would avoid unnecessary pytest waiting**

We could divide testing into layers:

| Test                      | When                        | Purpose                                |
| ------------------------- | --------------------------- | -------------------------------------- |
| Syntax and import checks  | After each batch            | Detect broken imports and basic errors |
| Targeted unit tests       | After implementing a module | Test only the new module               |
| Related integration tests | After connecting modules    | Test interactions                      |
| Full `pytest`             | At milestones               | Detect cross-module regressions        |
| Final full test           | Before GitHub push          | Verify the complete implementation     |

For example, instead of running:

```
pytest
```

after every small change, we could initially run:

```
pytest tests/unit/algorithms/test_planning.py -q
```

Then:

```
pytest tests/integration/ -q
```

And eventually:

```
pytest -q
```

We could also use parallel testing when the test suite supports it, such as `pytest-xdist`, but only after verifying that the tests are safe to run concurrently.
