## 4.5 Orthographic memory → Synaptic plasticity and neural learning

<AsyncImage query="biological synapse neurotransmitter vesicles presynaptic postsynaptic membrane scientific neuroscience illustration" aspectRatio="16:9" width="100%" fit="contain"/>

Your current memory stores:

- Lifetime counts.
- Recent counts.
- Contiguous character sequences.

These are useful statistical memory structures.

However, they should not be mistaken for a biological memory mechanism.

A neural memory model should have connections whose strengths change as neural populations repeatedly interact.

One candidate learning mechanism is spike-timing-dependent plasticity (STDP).

Its simplified mathematical form is:

\[
\Delta w=
\begin{cases}
A_+e^{-\Delta t/\tau_+} & \Delta t>0\\
-A_-e^{\Delta t/\tau_-} & \Delta t<0
\end{cases}
\]

Where:

- \(w\): synaptic connection strength.
- \(\Delta t\): difference between pre- and postsynaptic spike times.
- \(A_+\): potentiation magnitude.
- \(A_-\): depression magnitude.
- \(\tau_+\), \(\tau_-\): timing constants.

The model changes connection strengths depending on the relative timing of neuronal activity.

We should also investigate other plasticity mechanisms, including Hebbian learning, homeostatic regulation, and mechanisms of memory consolidation.

This would allow ORE to develop learned orthographic representations instead of merely recording how many times a character appeared.

Importantly, STDP is one candidate biological learning mechanism, not a complete explanation of how the brain acquires reading skills.

# 5. Introduce actual neural dynamics into ORE

So far, we have discussed the neural components.

But there is another fundamental requirement:

**Neural activity must evolve over time.**

Your current modules generally calculate their outputs immediately.

Neurons, however, have internal states that change over time in response to incoming signals.

This means ORE needs a neural simulation engine.

## 5.1 Model individual neurons

We can begin with the Leaky Integrate-and-Fire (LIF) neuron.

Its simplified membrane equation is:

\[
\tau_m\frac{dV_i}{dt}
=
-(V_i-V_{\text{rest}})
+
R_m I_i(t)
\]

Where:

- \(V_i\): membrane potential.
- \(V_{\text{rest}}\): resting potential.
- \(\tau_m\): membrane time constant.
- \(R_m\): membrane resistance.
- \(I_i(t)\): incoming current.

When membrane potential reaches a threshold:

1. The neuron generates a spike.
2. Its membrane potential resets.
3. A refractory period may temporarily prevent another spike.

This gives ORE a basic model of neuronal electrical activity.

We can subsequently introduce more detailed models when necessary.

## 5.2 Model synaptic connections

Every simulated neuron should be capable of receiving signals from other neurons.

For a simplified synaptic model:

\[
I_i(t)=\sum_j w_{ij}s_j(t)
\]

Where:

- \(w_{ij}\): strength of the connection.
- \(s_j(t)\): incoming synaptic activity.

We should distinguish excitatory and inhibitory connections.

This means that one neuron may increase another population's activity, while another neuron may suppress it.

These interactions are fundamental to building neural circuits.

This is important because brain processing is not necessarily a one-way sequence.

Higher-level representations can influence earlier processing.

We should investigate predictive coding as one possible implementation.

In a predictive coding model:

1. Higher-level populations generate predictions.
2. Those predictions influence lower-level populations.
3. Lower-level populations compare predictions with sensory input.
4. Prediction errors are propagated.
5. Neural activity evolves to reduce the relevant errors.

We should separately model the precision assigned to prediction errors.

This architecture has a substantial neuroscience foundation, but predictive coding remains a theoretical framework with competing explanations and unresolved implementation details. We should therefore compare it against other recurrent and feedforward models rather than declare it the definitive explanation of reading. <Cite refs={["turn147936search2","turn147936search7","turn147936search3"]}/>

I recommend separating ORE into two complementary systems.

<box border radius="lg" padding={3} gap={3}>
  <title size="xl">ORE dual architecture</title>
  <box gap={1}>
    <badge color="info">System 1</badge>
    **Functional abstraction engine**

    This contains the existing mathematical algorithms, interfaces, deterministic processing, and reference implementations.

    It provides reproducible baselines and allows us to measure whether the neural system performs the expected functions.
  </box>
  <divider color="subtle"/>
  <box gap={1}>
    <badge color="success">System 2</badge>
    **Neural mechanism simulation engine**

    This contains neurons, synapses, neural populations, connectivity, electrical dynamics, plasticity, neural feedback, and learning.
  </box>
  <divider color="subtle"/>
  <box gap={1}>
    <badge color="discovery">Integration</badge>
    **Neural-functional comparison engine**

    This compares the neural system's emergent behavior against the existing mathematical algorithms, behavioral observations, and available neuroscience evidence.
  </box>
</box>

This architecture is important because we should not discard working mathematics just because we are improving the biological fidelity of ORE.

For example, the existing relative-position calculation can serve as a baseline for evaluating whether the neural positional system learns similar relationships.

The existing visual encoder can serve as a benchmark against which the neural visual representation is evaluated.

This gives us two implementations of related functions, with measurable differences.

# 7. How to make the neural mechanisms actually work

We need to be careful here.

Simply creating Python classes called `Neuron`, `Synapse`, or `BrainRegion` will not make ORE biologically meaningful.

The components must implement equations describing the processes they represent.

I recommend three computational foundations.

## Foundation A: Neural population dynamics

Before implementing thousands of individual spiking neurons, start with populations whose activity changes over time.

A simplified rate-based neural population could follow:

\[
\tau\frac{d\mathbf r}{dt}
=
-\mathbf r+
\phi(W\mathbf r+\mathbf I)
\]

This models the evolution of population activity according to its incoming signals and connection strengths.

Advantages:

- Computationally efficient.
- Easier to debug.
- Suitable for modeling interactions between brain regions.
- Suitable for testing recurrent feedback.
- Easier to compare alternative neural architectures.

## Foundation B: Spiking neural populations

Once the population-level architecture is working, introduce LIF neurons.

Each neuron maintains its own membrane potential, receives synaptic inputs, and generates spikes.

This allows us to study:

- Spike timing.
- Neural synchronization.
- Population firing rates.
- Temporal propagation.
- Synaptic plasticity.

## Foundation C: Biological learning

Introduce learning mechanisms that modify synaptic strengths.

We can implement several selectable approaches:

| Learning mechanism | Intended purpose |
|---|---|
| Hebbian learning | Strengthening correlated neural activity |
| STDP | Learning based on spike timing |
| Homeostatic plasticity | Maintaining stable neural activity |
| Competitive learning | Developing selective neural representations |
| Experience-dependent learning | Developing specialized orthographic representations |

We should not assume that one learning rule explains all of these processes.

Each mechanism should have its own mathematical specification, experimental justification, and validation tests.

**My recommendation is to begin with population dynamics, then add spiking neurons, and finally progressively introduce biologically grounded learning.**

This will avoid creating a highly complex simulator before we understand whether the basic neural architecture is correct.

# 8. How will we know that ORE is reproducing brain mechanisms?

This is arguably the most important part of the entire project.

We need to establish scientific acceptance criteria before implementing the neural system.

Otherwise, we could spend months creating sophisticated simulations that have little correspondence to actual neural mechanisms.

I recommend five validation dimensions.

<box border radius="lg" padding={3} gap={3}>
  <title size="lg">Neural reproduction acceptance framework</title>
  <list marker="number" gap={3}>
    <list-item>
      **Behavioral equivalence**

      Does the system recognize characters, preserve ordering, distinguish ambiguous patterns, and generalize to unseen visual variations?
    </list-item>
    <list-item>
      **Representational equivalence**

      Do the simulated neural populations represent visual features, letter identities, positional information, and increasingly abstract orthographic structures in ways consistent with observed neural representations?
    </list-item>
    <list-item>
      **Temporal equivalence**

      Does information propagate through the simulated network with temporal patterns compatible with empirical observations?
    </list-item>
    <list-item>
      **Connectivity equivalence**

      Do the modeled interactions between populations correspond to known anatomical and functional connectivity constraints?
    </list-item>
    <list-item>
      **Causal equivalence**

      When we disable or alter a particular neural population or connection, does the system produce the predicted impairment?
    </list-item>
  </list>
</box>

Here are some examples.

| Experiment | Expected observation |
|---|---|
| Remove early visual input | Recognition should deteriorate |
| Disable orientation-selective populations | Sensitivity to relevant visual features should decrease |
| Disable positional pathways | Letter-order errors should increase |
| Disrupt recurrent feedback | Some context-dependent processing should deteriorate |
| Prevent synaptic learning | Experience-dependent improvement should be impaired |

These are predictions to test, not guaranteed outcomes.

## 8.1 Compare neural representations against real brain measurements

Eventually, ORE should be evaluated against human neuroscience data.

We can use:

- fMRI for spatial patterns of brain activity.
- EEG and MEG for temporal dynamics.
- Intracranial recordings where suitable research datasets are available.
- Behavioral experiments for recognition and error patterns.

One particularly useful technique is Representational Similarity Analysis (RSA).

It allows us to compare the similarity relationships between patterns generated by ORE and those measured in the brain.

For example:

\[
D_{\text{brain}}(i,j)
\]

represents the dissimilarity between two brain-response patterns, while:

\[
D_{\text{ORE}}(i,j)
\]

represents the corresponding dissimilarity between two ORE neural population patterns.

We can compare them using a correlation:

\[
\rho=
\operatorname{corr}
\left(
D_{\text{brain}},
D_{\text{ORE}}
\right)
\]

A stronger correspondence would provide evidence that the two systems organize the tested representations similarly.

However, representational similarity alone does not establish that the systems use the same underlying neural mechanisms. That requires additional temporal, connectivity, and causal tests.

# 9. The proposed development trajectory

I would introduce a dedicated biological-development track alongside the existing ORE stages.

I would not prematurely renumber or replace Stages A–J.

Instead, these would be new development phases within the long-term ORE roadmap.

<box border radius="lg" padding={3} gap={3}>
  <title size="xl">ORE Neurocomputational Development Roadmap</title>
  <text color="secondary" size="sm">Proposed sequence, with acceptance gates between phases.</text>
  <list connector="solid" marker="number" gap={3}>
    <list-item>
      **Phase N1 — Neural simulation foundations**

      Implement neuron state, membrane dynamics, firing, synaptic transmission, populations, and simulation time.

      Acceptance: independently tested neuron and population dynamics.
    </list-item>
    <list-item>
      **Phase N2 — Biological visual processing**

      Introduce retinal/LGN-inspired processing and V1-like receptive fields, orientation selectivity, contrast sensitivity, and spatial organization.

      Acceptance: visual response properties verified against defined experiments.
    </list-item>
    <list-item>
      **Phase N3 — Hierarchical visual architecture**

      Implement intermediate visual representations and ventral visual processing.

      Acceptance: increasing feature abstraction and measurable visual invariance.
    </list-item>
    <list-item>
      **Phase N4 — Neural orthographic representations**

      Implement distributed letter representations, identity populations, absolute and ordinal position coding, and neural sequence processing.

      Acceptance: character and sequence recognition with independent generalization.
    </list-item>
    <list-item>
      **Phase N5 — Neural connectivity and recurrence**

      Introduce excitatory/inhibitory interactions, long-range connections, feedback, and recurrent processing.

      Acceptance: reproducible network dynamics and experimentally testable feedback effects.
    </list-item>
    <list-item>
      **Phase N6 — Biological learning and memory**

      Implement Hebbian mechanisms, STDP, homeostatic regulation, and experience-dependent specialization.

      Acceptance: learning and retention demonstrated without relying solely on fixed character prototypes.
    </list-item>
    <list-item>
      **Phase N7 — Predictive and contextual processing**

      Implement candidate predictive coding mechanisms, uncertainty, precision modulation, and comparisons against alternative recurrent models.

      Acceptance: predictions and prediction errors tested against independently specified experimental conditions.
    </list-item>
    <list-item>
      **Phase N8 — Brain-data validation**

      Compare behavioral results, neural representations, temporal activity, and connectivity against empirical datasets.

      Acceptance: reproducible results with held-out evidence and explicit limitations.
    </list-item>
    <list-item>
      **Phase N9 — Integrated neurocomputational ORE**

      Integrate the neural and functional engines, preserve previous stage compatibility, and establish comprehensive scientific acceptance reporting.

      Acceptance: complete regression suite and independently evaluated biological correspondence.
    </list-item>
  </list>
</box>

Each phase should produce reusable Python modules, mathematical specifications, experiments, trace files, regression tests, and a machine-readable acceptance report.

We should also preserve the provenance of every biological claim: whether an implementation is directly supported by experimental evidence, derived from a computational theory, or introduced as an engineering approximation.

This prevents theoretical assumptions from silently becoming established facts inside the software.

# 12. My ultimate recommendation

There is one principle I would like to establish for the entire future development of ORE:

**Every brain-related function that ORE implements should have two separate specifications:**

**A. Biological mechanism specification**

Explains what the brain appears to do, including:

- Relevant neural populations.
- Anatomical relationships.
- Electrical and chemical signaling.
- Neural dynamics.
- Learning mechanisms.
- Available experimental evidence.
- Unresolved scientific questions.

**B. Computational reproduction specification**

Explains how ORE will reproduce the proposed mechanism, including:

- Mathematical equations.
- Neural components.
- Connection structures.
- Processing algorithms.
- Learning rules.
- Python implementation.
- Experiments.
- Acceptance tests.
- Comparisons against experimental observations.

We should never allow a software implementation to become its own scientific justification.

The biological mechanism must guide the implementation, and independent evidence must evaluate it.

  <title size="2xl" color="success">A computationally reconstructed neural system</title>
  ORE begins with orthographic processing, but develops into a reusable framework for reproducing and investigating the neural mechanisms underlying different brain functions.

  The ultimate goal is not just to build an AI that recognizes what humans recognize.

  It is to construct an artificial system whose internal processes, interactions, learning mechanisms, and emergent representations are increasingly consistent with the biological processes that produce those abilities.
</box>

I would preserve this direction as a fundamental architectural principle throughout the ORE project.

**My strongest recommendation is to begin by implementing Phase N1, without modifying or discarding the existing Stage A–J implementations.** We should establish the neural engine first, then progressively connect it to the orthographic processing architecture.
