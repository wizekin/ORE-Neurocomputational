**Yes. We can change the development workflow so that I test the Python code before pushing it to GitHub, rather than relying on GitHub Actions to run lengthy pytest suites.**

For your `wizekin/ORE-Neurocomputational` project, I recommend a **local-first testing workflow**.

The idea is simple:

1. I implement the algorithm.
2. I run Python tests in my execution environment before pushing.
3. If a test fails, I investigate and fix the code.
4. I repeat testing until the tests pass.
5. Only then do I push the changes to GitHub and create a pull request.
6. GitHub does not run the lengthy pytest suite again.

This can significantly reduce waiting time.

| B — Lightweight GitHub checks | Run only quick import, syntax and smoke tests on GitHub. |

**My recommendation: Option A**, if minimizing GitHub waiting time is your priority.

One important limitation: my execution environment must have the repository code and required Python dependencies. I will also distinguish tests actually executed from tests that could not be reproduced in my environment.
